- ブランチ名: `phase5/5-3-week-tasks`（最新の main から分岐）

## 目的

週ビューを見るだけで、「この日が締切のやること」と「この予定までに残っているやること」が分かるようにする。

## 対象範囲

- 作るもの：週ビューの締切のチップ、予定の「やること 残り N」の印。
- 作らないもの：予定の作成・編集ダイアログからやることを足す導線（「やること」の画面の「予定」の欄で足せるようになったため、今回は作らない）、週ビューの中でやることを完了にする操作、「週末の1日」への表示、通知、プリント取り込み・重複からのやること。
- **サーバー側は変えない**（`src/worker`、`migrations` に変更を入れない）。やることは、既存の `GET /api/families/:id/tasks` から取得する。週 API も変えない。API に足りないものが見つかった場合は、変更を入れずに、PR の「未解決の点」に書いて止まる。

## データの取り方（画面）

- 週ビューは、週 API とは別に、やることの一覧を取得する。「やること」の画面と同じ query（`useTasksQuery`。鍵にユーザーと家族が入っている）を使い、キャッシュを共有する。
- **やることの取得を待たずに、週ビューを表示する。** やることが届いたら、チップと印を足す。届くまで・取得に失敗したとき・家族の準備ができていないときは、チップと印を出さないだけで、週ビューはこれまでどおり表示する（エラーの案内は出さない）。
- やることが届いてチップが足されたとき、すでに表示されている行やカードの並びが入れ替わらないこと（高さが増えるのはよい）。
- ログアウト・アカウント切替・家族の切替で、前のアカウント・家族のやることを表示しない。

## 計算（純粋関数にして `src/shared/domain` に置き、ユニットテストを付ける）

- **その日が締切のやること**：未完了で、期限の日（`Asia/Tokyo`）がその日のもの。
  - 日付だけの期限は、その日。日時の期限は、その時刻の日。持ち物からの自動のやること（期限は予定の前日 20:00）も同じ扱い。
  - 期限が「なし」「不明」のもの、完了したものは対象外。
  - 期限を過ぎたやることを、今日や後の日に繰り越して出さない（出すのは、期限の日だけ）。
  - 並び：期限の時刻が早い順（日付だけの期限は、その日の最後）。同じなら ID 順。
- **予定の残りの数**：その予定にひもづく、未完了のやることの数（期限に関係なく数える）。0 なら出さない。
- 日付と時刻の計算は、`src/shared/time` を通す。

## 画面（週ビュー）

### 締切のチップ

- 見た目：黄土色（`--deadline` のトークン）のチップと旗のアイコン、文字「締切 〈タイトル〉」。色だけで区別しない。
  - 予定にひもづくやることは、予定のタイトルを添える（例「締切 持ち物を準備（運動会）」）。予定の情報が取れていないときは、やることのタイトルだけ。
  - 長いタイトルは、チップの中で省略する（横にはみ出さない）。読み上げには、全文を入れる。
- 出す場所：
  - 通常の平日の行：ほかのチップ（ルーティンなど）のあとに並べる。
  - 「いつもと違う日」のカード、週末・祝日のカード：予定の並びのあとに、チップでまとめて出す。
- 1日に出すのは **2 件まで**。それより多いときは、2 件のあとに「ほか N 件」を出す。
- チップと「ほか N 件」は、「やること」の画面（`/tasks`）へのリンクにする（タップ領域は 44px 以上）。
- **締切があるだけでは、日のレイアウトを変えない**（通常の平日は、通常の行のまま。docs/03 の決まりどおり）。その日に予定がなく、締切だけがある日は、「予定なし」の低い行にせず、チップが見える通常の行にする。
- 「ルーティンを隠す」は、締切のチップを隠さない。
- 過去の日（今日より前）の締切のチップも、未完了なら出す（その週を見返したときに、やり残しが分かる）。

### 予定の「やること 残り N」

- 「いつもと違う日」のカードと、週末・祝日のカードの中の、**家族の単発の予定**に出す（例「やること 残り 2」。チェックのアイコンと文字）。持ち物の表示の近くに置く。
- 通常の平日の行のチップには出さない（狭いため）。繰り返し予定の回と、「自分だけ」の予定には出さない。
- **予定の行は、全体が1つの編集ボタンになっている。その中に、リンクやボタンを入れない**（入れ子にしない）。この印は、押せない表示にする。予定の編集ボタンの読み上げに、「やること 残り 2 件」を含める。

## 変えないもの

- 週 API、やることの API、D1 のスキーマ、スコープ。
- `dayLayout` の決まり（どの日がカードになるか）。予定の表示・編集・作成、重複の印、振替の印、空きタイムライン、「自分だけ」の予定。
- 「やること」「週末の1日」「繰り返し」「家族」の画面。
- 週ビューのスクリーンショットを書き出すテストは、いまの1つのまま（`e2e/week-busy.spec.ts`）。

## テスト

- ユニット：その日が締切のやること（日付だけ・日時・自動のやること、日付の境目 0 時前後、完了・期限なし・不明が対象外、繰り越さないこと、並び）、予定の残りの数（完了を数えない、0 のとき）。
- Playwright（API をモック、合成データ）：
  - 通常の平日の行、「いつもと違う日」のカード、週末のカードに、締切のチップが出ること。予定のタイトルが添えられること。
  - 3 件以上で「ほか N 件」になること。チップを押すと「やること」の画面が開くこと。
  - 予定がなく締切だけの日が、チップの見える行になること。締切があっても、通常の平日がカードにならないこと。
  - 「ルーティンを隠す」で、締切のチップが残ること。
  - カードの中の単発の予定に「やること 残り N」が出ること。0 件・繰り返し予定の回・「自分だけ」の予定には出ないこと。予定を押すと、これまでどおり編集ダイアログが開くこと（印が別の操作にならないこと）。
  - やることの取得を遅らせても、週ビューが先に表示されること。取得に失敗しても、週ビューが表示され、エラーの案内が出ないこと。
  - 「やること」の画面で完了にしてから週ビューに戻ると、チップと残りの数が減っていること。
  - アカウントを切り替えたとき、前のアカウントのやることのチップが表示されないこと。
  - 390px と 445px で横にはみ出さないこと（長いタイトルを含む）。リンクのタップ領域が 44px 以上であること。
- 既存のテストがすべて通ること。
