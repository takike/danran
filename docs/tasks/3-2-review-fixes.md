## 直近の回を出すために、シリーズの全期間の回を取得している（要修正）

`listUpcomingInstances`（`src/worker/routes/routines.ts`）が、`events.instances` を `timeMin = 1970-01-01`、`timeMax = 2051-01-01`、1ページ 2500 件、最大 25 ページで呼んでいる。終了日のない繰り返し予定では、2050 年までの回をすべて取得することになる（毎週1回で約 1,300 件、毎日なら約 9,000 件・4ページ）。これを、「繰り返し」の画面を開くたびに、シリーズの数だけ行う。

- 表示に必要なのは4件なのに、1シリーズで数千件・数 MB の応答を取得し、すべて検証している。Cloudflare Workers の CPU 時間の上限に当たるおそれがあり、Google への負荷も大きい。fetch のモックでは検出できない。
- `timeMin = いま` にすると「元は今後の回だが、過去に振り替えた回」が漏れる、という理由（docs/20 に記載）は正しい。その対処は、全期間ではなく、**限られた範囲**で行う。

直し方：

- 取得する範囲を、**今日の 31 日前から、今日の 120 日後まで**（`Asia/Tokyo` の日付で計算）にする。隔週の4回（8週間）と、休み・振替が続いた場合を見込んだ幅。
- 1ページの件数は 250、ページ数の上限は 4 にする。上限までに終わらない場合は、これまでどおりそのシリーズを「取得できませんでした」にする。
- 範囲の中で、元の予定日（`originalStartTime`）が今日以降の回を、元の予定日の順に並べて、最初の4件を返す（並べ方と状態の決め方は変えない）。
- 割り切り：元の予定日から 31 日より前に振り替えた回、120 日より先の回は、直近の回に出ない。docs/20 と docs/06 に、範囲とこの割り切りを書く。
- 範囲の計算（開始・終了の時刻）は `src/shared/time` のユーティリティを使う。

## 変えないもの

- 回の変更（休む・取り消す・振替）の API と検証、応答の形、画面、週ビューの案内文。
- シリーズ単位の並列数の上限（4）、失敗したシリーズだけを「取得できませんでした」にする扱い。

## テスト

- `events.instances` に送る `timeMin` / `timeMax` が、今日の 31 日前・120 日後であること（時刻を固定して検証する）。`maxResults` が 250 であること。
- 5ページ目が必要になる場合に、そのシリーズだけが「取得できませんでした」になること。
- 範囲の中で過去に振り替えた回（元の予定日は今日以降）が、直近の回に出ること。
- 既存のテストがすべて通ること（全期間の取得を前提にした期待値は、新しい範囲に合わせて直す）。
