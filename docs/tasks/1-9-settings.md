# タスク 1-9：設定（最小）— メンバーの名前・色、休園日

- ブランチ名: `phase1/1-9-settings`（最新の main から分岐）
- 作業前に読むもの: [AGENTS.md](../../AGENTS.md)、[docs/05-implementation-plan.md](../05-implementation-plan.md) の 1-9、[docs/12-time-and-layout.md](../12-time-and-layout.md)（休園日の節）、[docs/14-family-onboarding.md](../14-family-onboarding.md)、[docs/15-week-api.md](../15-week-api.md)、[docs/02-screens.md](../02-screens.md)（タブバー、メンバー色、アクセシビリティ要件）

## 目的

「家族」タブ（`/family`）で、メンバーの表示名と色を変えられ、休園日を登録・削除できるようにする。登録した休園日は、週ビューで週末カード扱いになる（週 API は 1-6 で対応済み）。

## 背景

- 実機確認で、大人2人の表示名がどちらも Google アカウントの氏名になり、凡例で区別できなかった。表示名を「パパ」「ママ」などに変えられる必要がある。
- `closure_days` テーブルと zod スキーマ（`src/shared/schemas/closure.ts`）は 1-5 で作成済みだが、登録する手段がまだない。

## 権限の方針（docs/06 に記録する）

- メンバーの名前・色の変更と、休園日の登録・削除は、その家族の active な大人のメンバーなら誰でもできる（オーナーに限定しない）。
- 子どもの追加・削除、招待の発行は従来どおりオーナー限定で、オンボーディング画面（`/onboarding`）に残す。このタスクでは変えない。

## API（すべて `familySecurityMiddleware` を通す）

共通：未ログインは 401、その家族の active メンバーでなければ 404。入出力は `src/shared/schemas` の zod スキーマで検証し、クライアントと共有する。変更系のボディサイズ上限は既存の変更系 API と同じにする。

### メンバー

- `PATCH /api/families/:id/members/:memberId`
  - 入力：`name`（既存の `memberNameSchema`）、`color`（既存の8色パレット）。
  - 対象はその家族の active メンバー（大人・子どもどちらも可）。ほかの家族のメンバー ID は 404。
  - 色の重複は許可する（画面で、使用中の色が分かるようにする）。
  - 変更できるのは `name` と `color` だけ。`kind`、`userId`、`sortOrder`、`status` は変えない。
  - 応答は更新後の家族（`GET /api/families/:id` と同じ形、同じ並び順）。

### 休園日

- `GET /api/families/:id/closures`：今日（Asia/Tokyo）以降の休園日を日付順で返す。件数の上限を設ける。
- `POST /api/families/:id/closures`
  - 入力：開始日、終了日（省略時は開始日と同じ）、ラベル（前後の空白を除いて1〜40文字）、対象メンバー ID の配列（空配列＝家族全員）。
  - 期間は最大31日。1日につき1行を作成する。同じ日・同じラベル・同じ対象の行が既にあれば重複して作らない。
  - 対象メンバー ID は、その家族の active メンバーだけを受け付ける。
  - 日付計算は `src/shared/time` を通す。祝日データの対応年（1970〜2050）の範囲外は 400。
- `DELETE /api/families/:id/closures/:closureId`：その家族の行だけ削除できる。既に無い場合も成功として扱う。
- D1 スキーマは変更しない想定。変更が必要になった場合は理由を PR に書く。

## 画面（`/family`）

- 「メンバー」：全メンバーを API の並び順で一覧表示し、それぞれ名前と色を編集できる。色は8色から選び、色名のラベルも出す（色だけで区別しない）。
- 「休園日」：今日以降の一覧（日付、ラベル、対象）と、追加フォーム（開始日、終了日、ラベル、対象メンバー）。各行に削除ボタン（画面内の確認表示を挟む）。
- 既存の「家族の設定」（`/onboarding` へのリンク）とログアウトは残す。
- 入力はすべて本物の `input` と `label`。タップ領域は 44px 以上。幅は `--app-max-width`。色・余白は `tokens.css` のトークン。
- 保存・削除は同期 ref で二重送信を防ぎ、処理中は無効にする。失敗時は入力を保持し、固定の日本語メッセージを出す。
- 入力中は `useReloadProtection` で自動再読み込みを保留する。
- 保存に成功したら、家族と週のクエリを再取得する（凡例の名前・色、週ビューの休園表示に反映される）。

## 週ビュー

- 休園日が週末カード扱いになり、ラベルのチップが出ることを、実データの流れ（登録 → 週ビュー）で確認する。週 API や `dayLayout` の仕様は変えない。
- 色名「石板」は分かりにくいので、UI の表示名を「グレー」に変える（識別子 `slate` は変えない）。docs/02・06・09・14 の表記も合わせる。

## テスト

- API（Vitest）：メンバー更新の正常系（オーナー以外の大人が実行できること）、401 / 404（非メンバー、他家族のメンバー ID）、入力検証、変更不可の項目が変わらないこと。休園日の作成（単日・期間・31日超の拒否・重複の抑止）、一覧の範囲と順序、削除（他家族の行は消せない、存在しない行も成功）、対象メンバーの検証。
- 週 API：登録した休園日の日が `weekend-card` になり、`closures` にラベルが出ること。
- Playwright（API をモック）：名前と色の変更、休園日の追加と削除、入力エラー、連打しても送信が1回であること、390px と 445px で横スクロールが出ないこと。
- 既存のテストがすべて通ること。
