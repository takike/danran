## 背景

2026-10-04 に人間が staging で S1 を Android 実機（CSS 幅 約445px）で確認した。表示とデータの取得は正しく動いている。以下は見た目と細部の修正。

## やること

1. **画面幅**
   - いまは全ページが最大幅 390px 固定で、幅の広いスマホでは左右に大きな余白が出て、タブバーも画面幅いっぱいにならない。
   - 最大幅をトークン（例 `--app-max-width: 480px`）にし、それ以下の画面では幅いっぱいに使う（左右の余白は既存の spacing トークン）。それより広い画面では中央寄せのまま。
   - タブバーは背景と上の線を画面幅いっぱいにし、中の項目だけ同じ最大幅に収める。
   - 対象は共通の枠を使っている全ページ（ホーム、週ビュー、家族、オンボーディング、招待、準備中、プライバシー）。
   - 更新バナー（`src/client/features/pwa/PwaUpdateBanner.tsx`）も 390px 固定になっているので、同じトークンに合わせる。`max-w-[390px]` の直書きがほかに残っていないか検索して確認する。

2. **月の見出し**
   - 同じ年の中で月をまたぐ場合は「2026年9月〜10月」とする。年をまたぐ場合だけ「2026年12月〜2027年1月」。

3. **予定のない平日の行**
   - compact の日で表示する予定がない場合は「予定なし」の文字を出さず、行の高さを詰める（日付と曜日だけの行。スクリーンリーダー向けには「予定なし」を残す）。
   - 週末・祝日のカードの「予定なし」は現状のまま。

4. **表示できる予定がない expanded の日**
   - layout が expanded でも、画面に出す予定が0件なら compact の行として表示する（「いつもと違う日」ラベルと「予定なし」が同時に出ないようにする）。
   - source が `publish` の予定を画面側で隠すのをやめ、通常の家族予定として表示する（家族カレンダー上の予定なので、家族に見えてよい）。docs/02 と docs/06 の記述も合わせる。

5. **週の切り替え**
   - 前週・次週を押したとき、新しい週が届くまで前の週の表示を残す（TanStack Query の `placeholderData` を使う）。取得中であることは控えめに示し、前週・次週ボタンは無効にしない。
   - エラーになった場合は、前の週の内容を残さずエラー表示に切り替える。

6. **メンバーの並び順**
   - 招待で参加した大人と子どもの `sort_order` が重複する（どちらも 1 になる）。参加時は、その家族の既存メンバーの最大値 + 1 を割り当てる。
   - 表示順は API 側で安定させる：大人 → 子ども、同じ種別の中では sortOrder → id。`GET /api/families` と `GET /api/families/:id/week` の両方に適用する。
   - 既存データを書き換えるマイグレーションは作らない。

## テスト

- Playwright：390px と 445px の両方で横スクロールが出ないこと、445px で内容とタブバーが画面幅を使っていること。月の見出し（同年・年またぎ）。予定のない平日の行。publish の予定が表示されること。表示予定0件の expanded が compact になること。週の切り替え中に前の週が残り、エラー時は残らないこと。
- Vitest：参加時の sort_order、メンバーの並び順（重複した既存データでも安定すること）、月の見出しの整形。
- 既存のテストがすべて通ること。
