# タスク：「繰り返し」の画面の待ち時間と、操作後のちらつきを減らす

- ブランチ名: `perf/routines-responsiveness`（最新の main から分岐）
- 作業前に読むもの: [AGENTS.md](../../AGENTS.md)、[docs/20-routines.md](../20-routines.md)、[docs/11-google-calendar-client.md](../11-google-calendar-client.md)、`src/worker/google/calendar.ts`（`createGoogleCalendarClient` の第3引数 `reuseAccessToken` / `maxExternalRequests`）、`src/worker/google/requestBudget.ts`、`src/worker/routes/routines.ts`、`src/client/features/routines/`
- **人間の確認が必要**（Google のアクセストークンの扱いに触る）

## 背景

実機確認で、次の2点の指摘があった。

1. 「繰り返し」の画面に切り替えたとき、表示まで1秒ほどかかる。
2. 「この回を休む」を押したあと、画面がカクカクする（表示が何度か入れ替わる）。

原因として分かっていること：

- 一覧の取得（`GET /routines`）は、繰り返し予定ごとに Google を2回（本体と直近の回）、加えて全体で1回（重複の確認用）呼ぶ。**Google を呼ぶたびに、アクセストークンを取り直している**ので、外部への通信がほぼ2倍になっている。PR #32 で、1つのリクエストの中だけでトークンを使い回す指定（`reuseAccessToken`）が入ったが、いまは祝日スキップの2つの API しか使っていない。
- 回の操作（休む・取り消す・振替）のあと、画面は一覧全体を取り直している。その間に、応答で受け取った回の表示・取り直し中の表示・取り直し後の表示が順に入れ替わる。

## 目的

「繰り返し」の画面を開いたときの待ち時間を減らし、回を操作したあとの表示の入れ替わりをなくす。

## 対象範囲

### サーバー（`src/worker/routes/routines.ts` だけ）

- `routines.ts` の中で `createGoogleCalendarClient` を呼んでいるすべての箇所で、`reuseAccessToken: true` を指定する（一覧、作成、削除、回の操作。祝日スキップの2つは指定済み）。トークンは、そのリクエストの処理の間だけ、メモリ上で使い回す。保存しない。リクエストをまたいで使い回さない。
- 一覧（`GET /routines`）には、外部リクエスト数の上限（`maxExternalRequests`）も付ける。値は、いまの呼び出し方で「繰り返し予定 10 件」が収まる数にし、根拠を docs に書く。上限に達したときは、いまの失敗時の扱い（そのシリーズの直近の回や、重複の確認を「取得できませんでした」にする）に乗せ、一覧そのものは返す。
- 一覧の中の Google の呼び出しの並び（並列数 4、重複の確認は全体で1回）は変えない。
- **ほかのルート（週、個人予定、空き状況、予定、家族）のクライアントの作り方は変えない。** 広げるかどうかは、このタスクの結果を見て別に決める。
- `src/worker/google/` の実装は、必要がなければ変えない。変える必要が出た場合は、既定の動き（第3引数なし）が変わらないことをテストで示す。

### 画面（`src/client/features/routines/`）

- 回を操作したとき（休む・取り消す・振替）：
  - 応答で受け取った回の内容で、その回のチップをすぐに更新する（いまもしているなら、そのまま）。
  - そのあとの一覧の取り直しは、**裏で**行う。取り直しの間、一覧・カード・チップを読み込み中の表示に差し替えない。前の内容を表示したまま、届いたら差し替える。
  - 取り直しの結果で、カードの高さや並びが変わる場合（重複のパネルが消える、など）以外に、見た目が動かないこと。
- 祝日・年末年始の設定を切り替えたときの「適用中...」の表示は、いまのまま（処理に時間がかかるので、表示が必要）。
- 画面を開いたとき：一覧の取得が終わるまでの表示を、いまの「読み込み中」の文字だけから、カードの形をした控えめなプレースホルダー（2件分）にする。取得が終わったときに、ページ全体の高さが大きく跳ねないようにするため。
- 別のタブから戻ってきたとき：前に取得した一覧があれば、それをすぐに表示し、裏で取り直す（空の画面や読み込み中の表示に戻さない）。別のアカウント・家族の内容を表示しないこと（query の鍵にユーザーと家族が入っている状態を保つ）。

## 変えないもの

- API の入出力、回の操作・祝日スキップ・重複の決まり。
- 認可、カレンダー ID の扱い、誰のトークンを使うか。
- D1 のスキーマ、マイグレーション、スコープ、デプロイ設定。

## テスト

- API：
  - 一覧の取得で、トークンの取得（Google の token エンドポイントへの通信）が、**1回のリクエストにつき1回**であること（繰り返し予定が複数ある場合で確かめる）。回の操作でも同じ。
  - Google が 401 を返したときは、取り直して1回だけやり直すこと（既存の挙動が保たれていること）。
  - リクエストをまたいでトークンを使い回さないこと（2回のリクエストで、トークンの取得が2回）。
  - 外部リクエスト数の上限に達したとき、一覧は返り、該当の部分だけが「取得できませんでした」になること。
  - ほかのルート（週、個人予定、空き状況）の、トークンの取得の回数が変わっていないこと。
- Playwright（API をモック。一覧の応答を遅らせる）：
  - 回を休みにしたあと、一覧の取り直しの間も、カードとチップが表示されたままで、読み込み中の表示に切り替わらないこと。
  - 別のタブへ移って戻ったとき、前の一覧がすぐに表示されること。
  - アカウントを切り替えたとき、前のアカウントの一覧が表示されないこと。
  - 初回の表示で、プレースホルダーが出ること。
- 既存のテストがすべて通ること。

## 受け入れ基準

- 「繰り返し」の一覧の取得で、Google のトークンの取得が1回のリクエストにつき1回になっている。
- 回を操作したあと、一覧の取り直しの間に、表示が読み込み中に切り替わらない。
- `routines.ts` 以外のルートの挙動が変わっていない。
- `pnpm typecheck` / `lint` / `test` / `e2e` が通る。`pnpm db:generate` で差分が出ない。
