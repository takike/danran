# タスク：週ビューの「いつもと違う日」のカードを小さくし、「＋」をカードの外に出す

- ブランチ名: `phase3/s1-compact-unusual-day-card`（最新の main から分岐）
- 作業前に読むもの: [AGENTS.md](../../AGENTS.md)（UI の規約）、[docs/01-concept.md](../01-concept.md)（「ルーティンは背景に」）、[docs/02-screens.md](../02-screens.md)（S1 の平日セクション）、`src/client/features/week/WeekPage.tsx`（`ExpandedDay`、`CompactDay`、`AddDayButton`、`EventEditButton`）

## 背景

実機確認（Android、CSS 幅 約445px）で、平日の「いつもと違う日」のカードについて、次の2点の指摘があった。

1. カードが大きい。予定が1件だけでも約 124px の高さがあり、前後の平日の行（約 40px）に比べて目立ちすぎる。
2. 予定の追加の「＋」がカードの中に入り込んでいて、ほかの日の「＋」（行の右端）と位置がそろわず、カードやその中の印（「繰り返し」「振替（10/20 から）」）とぶつかって見える。

いまの作り：カードの中に、1段目「いつもと違う日」のラベルと「＋」（44px）、2段目に時刻と印、3段目にタイトル（最小 44px、上に余白）、が縦に積まれている。

## 目的

「いつもと違う日」のカードを、予定の内容が読める範囲でできるだけ低くする。「＋」は、ほかの平日の行と同じ位置（行の右端、カードの外）にそろえる。

## 対象範囲（`ExpandedDay` だけ）

### 「＋」の位置

- 「＋」をカードの外に出し、平日の通常の行（`CompactDay`）と**同じ横位置**（行の右端）に置く。縦は、カードの上端にそろえる。
- 行の構成は「日付｜カード｜＋」の3列にする。カードは、日付と「＋」の間の幅を使う。
- 「＋」の大きさ（44px 以上のタップ領域）、`aria-label`、押したときの挙動は変えない。

### カードの中

- 1段目：「いつもと違う日」のラベルだけ（小さく。カードの上の余白を詰める）。予定が0件のときの「予定なし」は、これまでどおりラベルの横。
- 予定1件ごとに、次の2行にまとめる（行の間に余分な余白を入れない）。
  - 1行目：時刻（左）と、印（右。「繰り返し」「振替（10/20 から）」「時間変更」「候補」「担当 …」）。
  - 2行目：対象メンバーの色の点と名前、タイトル。
- タップ領域は、**予定1件の2行をまとめて1つのボタン**にして、合わせて 44px 以上を確保する（タイトルの行だけで 44px を取らない）。押したときの挙動は変えない。
- 持ち物チップ、「自分だけ」の予定の行は、いまの見た目のまま、上下の余白だけを詰める。
- 予定と予定の間は、細い区切り線か小さな余白（`--spacing-xs`）にする。
- カードの内側の余白は `--spacing-sm` を上限に詰める。

### 高さの目安（445px 幅と 390px 幅の両方で）

- 予定が1件（印が1行に収まる場合）のカードの高さ：**88px 以下**。
- 予定が2件：**150px 以下**。
- 印が1行に収まらず折り返す場合は、その分だけ伸びてよい。文字は重ならないこと。

## 変えないもの

- どの日が「いつもと違う日」になるかの決まり（レイアウトの判定）。
- 平日の通常の行（`CompactDay`）、週末・祝日のカード、「週末の1日」。
- 予定の文言・印の内容・色、「自分だけ」の予定の見た目、編集や案内の挙動。
- `src/worker`、`src/shared`、`migrations`。

## テスト

- Playwright（API をモック、合成データ）
  - 「いつもと違う日」の行で、「＋」の左端・右端の位置が、通常の平日の行の「＋」と一致すること（±1px）。「＋」がカードの外にあること（カードの枠と重ならないこと）。
  - 予定1件のカードの高さが 88px 以下、2件で 150px 以下であること（390px と 445px）。
  - 「＋」と、カードの中の印・タイトルの表示領域が重ならないこと。
  - 予定のボタンのタップ領域が 44px 以上であること。押すと、単発の予定は編集ダイアログ、繰り返しの回は「繰り返し」タブへの案内が出ること（挙動が変わっていないこと）。
  - 印が多い予定（繰り返し＋振替＋担当）と、長いタイトルで、文字が重ならず、横にはみ出さないこと。
- 既存のテストがすべて通ること（高さや位置を前提にした期待値は、新しい見た目に合わせて直す）。
