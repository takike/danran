## 方針（2026-10-06 に人間が決定）

docs/03 と docs/05 は「月1回の Cron で適用する」としていたが、**Cron は使わない**。利用者が操作しているときにだけ、その人のトークンで Google カレンダーを変更する。

- 設定をオンにしたとき：今後6か月分の、該当する回をお休みにする。
- その後：誰かが「繰り返し」の画面を開いたときに、先の分を継ぎ足す。
- 割り切り：半年以上、誰も「繰り返し」の画面を開かなければ、その先の該当する回はお休みにならない。Cron は、必要になったら別のタスクで足す。
- docs/03・docs/05・docs/06 を、この方針に直す。

## 対象範囲

- 作るもの：繰り返し予定ごとの「祝日はお休み」「年末年始はお休み」の設定、該当する回の自動のお休み、設定をオフにしたときの復元、先の分の継ぎ足し。
- 作らないもの：**休園日に当たる回のスキップ**（計画では 3-3 に含まれていたが、休園日は対象メンバーごとの設定で、どの繰り返し予定に効かせるかの決まりが要るため、別のタスクにする）。年末年始の期間を家族ごとに変える設定（12/29〜1/3 で固定）。Cron。重複の検出（3-4）。

## データ

Drizzle のスキーマ → `pnpm db:generate` で**新しいマイグレーション**を作る。既存のマイグレーションは編集しない。既存の行は消さず、書き換えない。

- 新しいテーブル `routine_auto_skips`（自動でお休みにした回の記録）
  - 持つもの：ID、`routine_settings` の ID（シリーズの削除に連動して消える）、その回の元の開始日時、理由（`holiday` 祝日／`new_year` 年末年始）、作成の時刻。
  - `(routine_settings の ID, 元の開始日時)` は一意。
  - 予定のタイトルや内容は保存しない。
  - 目的：利用者が手動でお休みにした回と区別し、設定をオフにしたときに、自動でお休みにした回だけを元に戻すため。
- `routine_settings` に列 `auto_skip_applied_until`（日付、NULL 可）を足す。どの日までの回に、自動のお休みを適用し終えたかを持つ。
- `skip_holidays` と `skip_new_year` は、3-1 で作った列をそのまま使う。

## 決まり（純粋関数にして `src/shared/domain` に置き、ユニットテストを付ける）

- 対象の日：`skip_holidays` がオンなら日本の祝日（振替休日を含む。`src/shared/time/holiday.ts`）。`skip_new_year` がオンなら 12/29〜1/3（`isYearEndBreak`。期間が違う場合は、12/29〜1/3 になるように直す）。両方に当たる日（1/1）の理由は `holiday` とする。
- 対象の回：**元の予定日**（`originalStartTime` の `Asia/Tokyo` の日付）が対象の日で、今日以降のもの。
- 自動でお休みにするのは、**通常の回だけ**。すでにお休みの回、振り替えた回・時刻を変えた回は、触らない（記録も作らない）。
- 適用する範囲：今日から 183 日後まで。

## API（`familySecurityMiddleware` を通す。入出力は共有の zod スキーマ）

共通：未ログインは 401、その家族の active な大人のメンバーでなければ 404。カレンダー ID は DB の値だけを使う。Google への呼び出しはリクエストした本人のトークンで行い、`sendUpdates` は `none`。変更系の検査は既存の変更系 API と同じ。ほかの家族の `routineId` は 404。

- `PATCH /api/families/:id/routines/:routineId/settings`
  - 入力：`skipHolidays`、`skipNewYear`（どちらも真偽。両方必須）。
  - 設定を保存してから、下の「適用」を行う。オフにした理由については、下の「復元」を行う。
- `POST /api/families/:id/routines/:routineId/auto-skips/apply`
  - いまの設定で「適用」を行う（先の分の継ぎ足し用。何度呼んでも同じ結果になること）。
- **適用**：範囲の中の回を `events.instances` で取得し（3-2 と同じく、範囲を限定し、ページ数に上限を付ける）、対象の回を `events.patch` で `status: "cancelled"` にして、`routine_auto_skips` に記録する。終わったら `auto_skip_applied_until` を更新する。
- **復元**：オフにした理由の記録のうち、元の予定日が今日以降のものについて、その回がまだお休みなら、`status: "confirmed"`・元の日時に戻し（3-2 の「休みを取り消す」と同じ内容）、記録を消す。過去の回の記録は、そのまま消す（Google は変えない）。
- **1回のリクエストで変更する回の数に上限を付ける**（20 回）。残りがあるときは、応答で「続きがある」ことを返し、画面が同じ API をもう一度呼ぶ。Cloudflare Workers の外部リクエスト数の上限に当たらないようにするため。
- **途中で失敗しても、やり直せること**：Google を変更してから記録を書く。記録を書けなかった回は、次の適用で「すでにお休みの回」として触らない扱いになってしまうので、Google を変更する前に記録を書き、Google の変更に失敗したら記録を消す、の順にする（どちらの順でも、再実行で食い違いが残らないことをテストで確かめる）。
- `GET /api/families/:id/routines` の各項目に、`skipHolidays`、`skipNewYear`、`autoSkipDue`（継ぎ足しが必要か。設定がオンで、`auto_skip_applied_until` が今日の 150 日後より前なら true）を足す。直近の回（`upcoming`）の各回に、`autoSkipReason`（`holiday`／`new_year`／`null`）を足す。**GET では Google を変更しない。**

### 3-2 の API との関係（変更が要る）

- 利用者が、自動でお休みになった回を手動で操作したとき（休みを取り消す、振替を設定する）は、その回の `routine_auto_skips` の記録を消す。以後、その回は利用者が決めたものとして扱い、設定をオフにしても変更しない。
- ただし、設定がオンのまま、利用者が「休みを取り消した」回を、次の適用でまたお休みにしてしまわないこと。そのために、取り消した回は「適用しない回」として覚えておく必要がある。`routine_auto_skips` の行を消す代わりに、状態（`applied` 適用済み／`overridden` 利用者が上書き）を持たせる。`overridden` の回は、適用でも復元でも触らない。
- シリーズ全体の削除では、記録も消える（外部キーの連動）。

## 画面（`/routines`）

- 繰り返し予定のカードに、設定のトグルを2つ足す：「祝日はお休み」「年末年始はお休み（12/29〜1/3）」。本物のチェックボックスかスイッチ（`<input type="checkbox">` と `<label>`）にする。
- 切り替えると、すぐに保存して適用する。処理中は、そのカードの操作を無効にして「適用中...」と出す。続きがある場合は、画面が自動で続きを呼び、終わるまで「適用中...」のままにする。失敗時は、固定の日本語の案内と「もう一度試す」を出す（トグルは、サーバーに保存された状態を表示する）。
- 終わったら、直近の回のチップを更新する。自動でお休みになった回は、「10/12（月）お休み（祝日）」「12/29（火）お休み（年末年始）」のように、理由を添える。手動のお休みは、これまでどおり「お休み」。
- 画面を開いたとき、`autoSkipDue` が true の繰り返し予定があれば、画面が `auto-skips/apply` を呼ぶ（一覧の表示は待たせない。失敗しても一覧は表示し、控えめな案内だけ出す）。
- 週ビューと「週末の1日」は変えない（お休みの回は、これまでどおり出ない）。

## 変えないもの

- 繰り返し予定の作成・削除、手動の休み・振替の画面と挙動（上の「3-2 の API との関係」に書いた記録の扱いを除く）。
- 週 API、単発の予定、個人予定・空き状況。
- 既存のマイグレーションファイル、スコープ、デプロイ設定（Cron を足さない）。

## テスト

- ユニット：対象の日の判定（祝日、振替休日、12/29〜1/3、両方に当たる日）、対象の回の選び方（通常の回だけ、今日以降、範囲の端）。
- API：
  - オンにする：該当する回だけがお休みになり、記録が作られること。すでにお休みの回・振り替えた回を触らないこと。Google に送る本文。
  - オフにする：自動でお休みにした回だけが元に戻り、手動でお休みにした回は戻らないこと。
  - 利用者が取り消した回を、次の適用でまたお休みにしないこと。オフにしたときも触らないこと。
  - 上限（20 回）と「続きがある」の応答、続きの呼び出しで残りが処理されること、同じ呼び出しの繰り返しで結果が変わらないこと。
  - 途中の失敗（Google の失敗、D1 の失敗）からの再実行で、食い違いが残らないこと。
  - `autoSkipDue` の判定、GET で Google の変更が呼ばれないこと。
  - 認可：未ログイン 401、非メンバー 404、ほかの家族の `routineId` は 404、変更系の検査。
  - マイグレーション：新しいテーブルと列だけを足し、既存の行が残ること。
- Playwright（API をモック）：トグルの切り替え、「適用中...」、続きの自動呼び出し、失敗と再試行、チップの理由の表示、画面を開いたときの継ぎ足し、390px と 445px。
- 既存のテストがすべて通ること。

## 受け入れ基準

- 「祝日はお休み」をオンにすると、今後6か月の祝日に当たる回が、Google カレンダーでもお休みになる。オフにすると、自動でお休みにした回だけが元に戻る。
