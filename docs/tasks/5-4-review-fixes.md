## 指摘 1（修正が必要）：「習い事」の種類だけで作っている

`src/worker/routes/routines.ts` の回の操作で、`row.category === 'lesson'` のときだけ、欠席の連絡のやることを作っている。指示書の「作るのは、利用者が手動で『この回を休む』にしたとき」と違う（家事代行・その他の繰り返し予定を休んでも、作られない）。指示書の題名に「習い事の回」と書いたため、紛らわしかった（計画・レビュー担当の書き方の問題）。

### 直し方

- **種類に関係なく**、手動で休んだ回について作る（家事代行を休むときも、先方への連絡が要るため）。取り消し・振替・シリーズの削除で消すのも、種類に関係なく。
- 表示用のタイトルは、種類で言い方を変える：
  - 習い事：「〈タイトル〉（10/17（土））に欠席を連絡」（いまのまま）。
  - 家事代行・その他：「〈タイトル〉（10/17（土））のお休みを連絡」。
  - タイトルが分からないとき：「10/17（土）の欠席を連絡」（習い事）、「10/17（土）のお休みを連絡」（家事代行・その他）。
  - 種類は、一覧がすでに読んでいる `routine_settings` の行から取る。D1 に新しい列を足さない。繰り返し予定が消えていて種類が分からないときは、習い事の言い方にする。
- 「繰り返し」の画面の案内（「『欠席を連絡』をやることに追加しました」）も、種類に合わせる（家事代行・その他は「『お休みを連絡』をやることに追加しました」）。
- テスト：家事代行・その他の回を休んだとき・取り消したときの API と画面、表示用のタイトル（種類ごと、タイトルあり・なし）。いまの「習い事以外では作らない」テストは、新しい決まりに直す。
- docs/03・06・20・21 の説明を、新しい決まりに直す。

## 指摘 2（修正が必要）：シリーズの削除で、やることの削除に失敗すると、繰り返し予定の行が残る

`DELETE /routines/:routineId` で、欠席の連絡のやることの削除に失敗したとき、成功を返して処理を終えている。そのため、Google のシリーズは消えたのに、`routine_settings` の行が残り、「繰り返し」の画面に「見つかりません」のカードが残る。

### 直し方

- やることの削除に失敗しても、ログ（内容を含めない）に出すだけで、**`routine_settings` の削除まで進める**。応答は、これまでどおり。
- 残ってしまった欠席の連絡のやること（繰り返し予定がもうないもの）は、一覧ではタイトルなしの形で出て、完了にできればよい（いまの一覧の作りのまま）。この扱いを docs/21 に書く。
- テスト：やることの削除が失敗しても、`routine_settings` の行が消え、成功が返ること。残ったやることが、一覧でタイトルなしの形で返ること。

## 指摘 3（修正が必要。このタスクが原因ではない）：日付に依存したテスト

`test/routines.spec.ts` の次の3件は、実際の今日の日付を使っている。テストの中の回の日付（2026-10 中旬）が過去になったため、2026-10-14 から、main でも失敗するようになった。

- `uses one token per list request across parallel routines and the single conflict scan`
- `fits ten one-page routine series and one conflict scan inside the shared budget`

### 直し方

- 3件とも、ほかのテストと同じく、`vi.useFakeTimers({ toFake: ['Date'] })` と `vi.setSystemTime(...)` で、今日を固定する（テストの回の日付より前の日。期待値は変えない）。後片付け（`vi.useRealTimers()`）も、ほかのテストと同じにする。
- `test/` と `e2e/` のほかのテストで、同じく実際の今日に依存して、近いうちに失敗するものがないか探し、あれば同じく固定する（見つけたものを PR の説明に書く）。テストの意図を変えない。
- 確認：システムの日付を 2026-12-31 にずらして `pnpm test` を実行しても、通ること（PR の説明に、確かめた方法を書く）。
