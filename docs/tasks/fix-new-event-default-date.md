# タスク：23 時以降に「＋」から予定を追加すると、日付が翌日になる問題の修正

- ブランチ名: `fix/new-event-default-date`（最新の main から分岐）
- 作業前に読むもの: [AGENTS.md](../../AGENTS.md)（特に「絶対に守ること」2）、[docs/16-event-editing.md](../16-event-editing.md)、`src/shared/time/event.ts`（`getDefaultEventTime`）、`src/client/features/week/EventDialog.tsx`

## 背景

実機確認（2026-10-07 の 23 時台）で、週ビューの日ごとの「＋」から予定の追加を開くと、選んだ日の**翌日**が初期値になっていた。

原因：`getDefaultEventTime` は、時刻の初期値を「いまの次の正時から1時間」にしている。いまが 23 時台だと次の正時は 24 時になり、選んだ日に1日足している（`startHour >= 24 ? addCalendarDays(anchorDate, 1)`）。日を選んで開いたのに、別の日になってしまう。この計算は、平日の行でも週末・祝日のカードでも共通に使われている。

## 目的

日を選んで開いた予定の追加は、**必ずその日**が初期値になるようにする。

## 決まり（`getDefaultEventTime` を直す。純粋関数のまま、`Asia/Tokyo` で計算する）

| 開き方 | 開始日 | 開始〜終了の時刻 |
|---|---|---|
| 日ごとの「＋」で、選んだ日が今日 | 今日 | 次の正時から1時間。ただし、いまが 23 時台なら 23:00〜翌 0:00 |
| 日ごとの「＋」で、選んだ日が今日以外 | 選んだ日 | 10:00〜11:00 |
| 画面上部の「予定を追加」（日を選んでいない） | 今日 | 次の正時から1時間。ただし、いまが 23 時台なら 23:00〜翌 0:00 |

- どの場合も、開始日を翌日に繰り上げない。
- 終了が翌 0:00 になる場合（23:00 開始）の扱いは、いまの実装（終了日を翌日にする）のままでよい。
- 「週末の1日」の空きの帯から開く場合（開始時刻を渡す場合）は、この関数を使っていないので変えない。「家族の予定を追加」（その日を渡す）は、上の表の「日ごとの『＋』」と同じ扱いになる。

## 変えないもの

- 予定の作成・編集の API、フォームの項目と検証、保存の挙動。
- 編集で開いたときの初期値、空きの帯から開いたときの初期値。
- 繰り返し予定の作成フォームの初期値。

## テスト

- ユニット（`src/shared/time/event.spec.ts`）：上の表の各行。いまが 22:59・23:00・23:59（JST）のとき、今日・今日以外の日・日なしのそれぞれで、開始日が繰り上がらないこと。既存のテストのうち、23 時台に翌日へ繰り上がることを期待しているものは、新しい決まりに合わせて直す。
- Playwright：時刻を 23:30（JST）に固定して、平日の行の「＋」と、週末・祝日のカードの「＋」から開いたフォームの日付が、どちらも押した日になっていること。今日以外の日では、時刻が 10:00〜11:00 になっていること。
- 既存のテストがすべて通ること。
