# タスク 5-4：習い事の回を休みにしたら、「欠席を連絡」のやることを作る

- ブランチ名: `phase5/5-4-absence-tasks`（最新の main から分岐）
- 作業前に読むもの: [AGENTS.md](../../AGENTS.md)、[docs/03-architecture.md](../03-architecture.md)（「やること（tasks）の自動生成」の「重複」の行）、[docs/20-routines.md](../20-routines.md)、[docs/21-tasks.md](../21-tasks.md)、`src/worker/routes/routines.ts`（回の操作の共通処理、シリーズの削除）、`src/worker/routes/tasks.ts`（一覧、`AUTO_TASK_IMMUTABLE`）、`src/worker/db/schema.ts`（`tasks`）、`src/client/features/routines/RoutineInstances.tsx`、`src/client/features/tasks/`

## 方針（2026-10-12 に人間が決定）

docs/03 の「重複 → 〈習い事〉に欠席を連絡」のやることは、**習い事の回を休みにした時点で作る**（重なった時点では作らない）。

計画・レビュー担当が決めたこと（人間に報告済み。異論があれば、このタスクの中で直す）：

- 作るのは、利用者が**手動で**「この回を休む」にしたとき。重複の解決パネルから休んだ場合も、チップのメニューから休んだ場合も、同じ（どちらも、先方への連絡が要るため）。
- 祝日・年末年始の自動のお休みでは、作らない（先方も休みのため）。
- 振替（日時の変更）だけでは、作らない。

## 目的

習い事を休むと決めたら、「先方に欠席を連絡する」が、やることに自動で入る。休みを取り消したら、消える。

## データ

Drizzle のスキーマ → `pnpm db:generate` で**新しいマイグレーション**を作る。既存のマイグレーションは編集しない。既存の行は消さず、書き換えない。

- `tasks` に、一意の索引を1つ足すだけ：`source = 'conflict'` の行について、`(family_id, source_ref)` が一意。テーブルや列は足さない。
- 欠席の連絡のやることの行：
  - `source` は `conflict`。
  - `source_ref` は、`routine_settings` の ID と、その回の元の開始日時（`originalStart`）を組み合わせた文字列。
  - `title` は、固定の「欠席を連絡」を保存する。**習い事のタイトルは、D1 に保存しない**（これまでどおり Google カレンダーを正とする）。
  - 期限は、その回の元の予定日の**前日**（`Asia/Tokyo`。日付だけの期限）。元の予定日が今日か過去なら、元の予定日。期限は、作るときに決めて保存する（元の予定日は変わらないため）。
  - 担当は未設定。`event_meta_id` は空（予定にはひもづけない）。

## 決まり（純粋関数にして `src/shared/domain` に置き、ユニットテストを付ける）

- `source_ref` の作り方と読み方、期限の決め方、表示用のタイトルの作り方。
- 表示用のタイトル：「〈習い事のタイトル〉（10/17（土））に欠席を連絡」。習い事のタイトルが分からないときは「10/17（土）の欠席を連絡」。日付は、その回の元の予定日。
- 日付と時刻の計算は、`src/shared/time` を通す。

## サーバー

### 回の操作（`src/worker/routes/routines.ts`）

- **休む（`skip`）が成功したあと**：その回の欠席の連絡のやることを作る。すでにあれば、何もしない（同じ回を2回休んでも、1件）。
- **休みを取り消す（`restore`）・振替（`move`）が成功したあと**：その回の欠席の連絡のやることがあれば、消す（完了済みでも消す）。
- **シリーズ全体の削除**が成功したあと：そのシリーズの欠席の連絡のやることを、すべて消す。
- 祝日・年末年始の自動のお休み（適用・復元）では、やることを作らない・消さない。ただし、自動でお休みになった回を、利用者が取り消して、あらためて手動で休んだ場合は、手動の休みとして作る。
- **Google の変更が成功して、やることの更新だけが失敗した場合**：回の操作は成功として返す（応答は変えない）。やることは、次に同じ回を操作したときに正しい状態になればよい。失敗は、内容を含めずにログに出す（タイトル・日時・ID を出さない）。
- 回の操作の API の入出力、検証、Google への呼び出しの数と順序は変えない。

### やることの API（`src/worker/routes/tasks.ts`）

- 一覧（`GET /tasks`）：欠席の連絡のやることは、`title` を表示用のタイトルにして返す。習い事のタイトルは、一覧がすでに行っている家族カレンダーの取得（`events.list`）の結果から、そのシリーズの回（`recurringEventId` が一致するもの）のタイトルを使う。**Google への呼び出しを増やさない。** 欠席の連絡のやることしかない場合でも、タイトルのために1回取得してよい（取得は一覧全体で1回のまま）。取得できなかったとき・そのシリーズの回が見つからないときは、タイトルなしの形で返す。
  - `linkedEvent` は `none`、`source` は `conflict`、期限は保存した値。
- 更新（`PATCH`）：担当と、完了／未完了だけ変えられる。タイトル・期限・予定とのひもづけを変えようとしたら、`AUTO_TASK_IMMUTABLE`（持ち物の自動のやることと同じ）。
- 削除（`DELETE`）：できない（`AUTO_TASK_IMMUTABLE`）。休みを取り消せば消える。
- 認可は変えない。ほかの家族の欠席の連絡のやることは、見えず、変更もできない。

## 画面

### 「やること」（`/tasks`）

- 欠席の連絡のやることは、「予定に紐づかないやること」と「期限順」「自分の担当」に、ほかのやることと同じ行で出る。
- 発生元の表示は「お休みから自動」。タイトルを押しても、編集は開かない（持ち物の自動のやることと同じ）。完了と担当は、変えられる。

### 「繰り返し」（`/routines`）

- 回の操作（休む・取り消す・振替）が成功したら、やることの一覧のキャッシュも裏で取り直す（「やること」と週ビューの締切のチップに、すぐ反映されるように）。
- 「この回を休む」が成功したあと、その繰り返し予定のカードに、控えめな1行を出す：「『欠席を連絡』をやることに追加しました」と、「やること」へのリンク（タップ領域は 44px 以上）。別の操作をするか、画面を離れたら消える。先に表示を切り替える作り（PR #38）は、そのまま。
- それ以外の見た目・操作は変えない。

### 週ビュー

- 変えない。締切のチップ（5-3）は、期限のあるやることとして、そのまま出る。

## 変えないもの

- 回の操作・祝日スキップ・重複の決まりと API の入出力。回の操作を先に画面へ反映する作り。
- 持ち物からの自動のやること、手動のやること、予定の候補の API。
- 既存のマイグレーションファイル、スコープ、デプロイ設定。Cron を足さない。

## テスト

- ユニット：`source_ref` の往復、期限（前日、月や年をまたぐ前日、今日・過去の回）、表示用のタイトル（タイトルあり・なし）。
- API：
  - 休む → 1件できること（`source`、`source_ref`、期限、担当なし、D1 の `title` が固定の文字であること）。同じ回をもう一度休んでも、増えないこと。
  - 取り消す・振替 → 消えること（完了済みでも）。もともとない場合も、成功すること。
  - シリーズの削除 → そのシリーズの分だけ消え、ほかのシリーズ・手動・持ち物のやることが残ること。
  - 祝日・年末年始の適用と復元で、やることができない・消えないこと。
  - やることの更新が失敗しても、回の操作が成功として返ること。次の操作で、正しい状態になること。
  - 回の操作の Google への呼び出しの数が、増えていないこと。
  - 一覧：表示用のタイトル（習い事のタイトルが取れた場合・取れない場合・Google の取得の失敗）、Google の取得が一覧全体で1回のままであること。
  - 更新：担当と完了だけ。タイトル・期限・ひもづけは拒否。削除は拒否。
  - 認可：**ほかの家族の欠席の連絡のやることが、見えず、変更もできないこと**。
  - マイグレーション：索引を足すだけで、既存のテーブルと行を変えないこと。
- Playwright（API をモック、合成データ）：
  - 「繰り返し」で回を休むと、「『欠席を連絡』をやることに追加しました」が出て、リンクから「やること」が開くこと。取り消すと、案内が出ないこと。
  - 「やること」で、欠席の連絡のやることが「お休みから自動」と出て、タイトルを押しても編集が開かず、完了と担当は変えられること。
  - 週ビューで、期限の日に締切のチップが出ること。
  - 390px と 445px で横にはみ出さないこと。
- 既存のテストがすべて通ること。

## 受け入れ基準

- 習い事の回を手動で休みにすると、「〈習い事〉（日付）に欠席を連絡」のやることが1件でき、期限は前日になる。
- 休みを取り消す・振り替えると、そのやることが消える。
- 祝日・年末年始の自動のお休みでは、できない。
- 習い事のタイトルが、D1 に保存されていない。
- ほかの家族のやることを見ることも変更することもできないことが、テストで保証されている。
- `pnpm typecheck` / `lint` / `test` / `e2e` が通る。`pnpm db:generate` で差分が残らない。

PR を作成したらマージせずに止まること。
