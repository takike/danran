## 目的

家族の「やること」を一覧し、完了にする・担当を決める・手動で足す、をできるようにする。予定ごとにまとめて、「この予定までに何が残っているか」が一目で分かるようにする。

## 対象範囲

- 作るもの：`/tasks` の画面（いまは「準備中」）、API を呼ぶクライアントのコード。
- 作らないもの：週ビューへの表示（締切チップ、未完了の数。5-3）、予定の作成・編集ダイアログからやることを足す導線（5-3 で検討）、通知、プリント取り込み・重複からのやること。
- **サーバー側は変えない**（`src/worker`、`migrations` に変更を入れない）。API に足りないものが見つかった場合は、変更を入れずに、PR の「未解決の点」に書いて止まる。

## 画面（`/tasks`）

下のタブバーの「やること」から「準備中」の表記を外し、この画面を開く。ログインしていて、家族の準備ができている利用者だけが見られる（「繰り返し」の画面と同じ条件・同じ行き先）。

### ヘッダー

- 基準日（例「10/4（日）時点」。`Asia/Tokyo` の今日）、タイトル「やること」、追加ボタン（「＋」。`aria-label`「やることを追加」）。

### 切り替え（既存の `Segmented` を使う）

- 「予定ごと」（既定）／「期限順」／「自分の担当」。選んだ表示は、画面を開いている間だけ覚える（保存しない）。

### サマリー（表示だけ。押しても何も起きない）

- 「今日まで N」（強調）：未完了で、期限が今日の終わりまでのもの（過ぎているものを含む）。
- 「今週 N」：未完了で、期限が今週（月〜日）の終わりまでのもの。
- 「担当未定 N」：未完了で、担当がないもの。
- 期限が「不明」「なし」のものは、「今日まで」「今週」に数えない。

### 「予定ごと」

- 予定ごとのカードを、予定の開始が早い順に並べる。
  - 見出し：予定の日付（例「10/7」）、タイトル、対象メンバー（空なら出さない）。右に「あと N日」（今日なら「今日」、過ぎていれば「終了」）。3日以内は強調色にするが、文字で分かるので色だけに頼らない。
  - 進捗：完了数／総数のバーと、「1/3 完了」の文字。
  - やることの行（下の「行」）。未完了を上に、期限の早い順。完了は下に。
  - カードの最後に「＋ この予定にやることを追加」（その予定にひもづけて、追加フォームを開く）。
- 予定の情報が「見つかりません」（Google カレンダー側で消された）のものは、「予定が見つかりません」のカードにまとめる。「取得できませんでした」のものは、「予定の情報を取得できませんでした」のカードにまとめ、再試行を出す。
- 最後に、「予定に紐づかないやること（N件）」の折りたたみ（`<details>` と `<summary>`）。0件なら出さない。

### 「期限順」

- 未完了のやることを、期限の早い順に1列で並べる。期限が「なし」「不明」のものは最後。ひもづく予定があれば、行の中に予定のタイトルと日付を小さく添える。完了したものは、その下に「完了」の見出しでまとめる。

### 「自分の担当」

- ログイン中の利用者のメンバーが担当のものだけを、「期限順」と同じ並びで出す。0件なら「あなたが担当のやることはありません」。

### 行

- チェックボックス（本物の `<input type="checkbox">` と `<label>`。タップ領域は 44px 以上）。押すと、すぐに表示を切り替えて保存する。失敗したら、表示を元に戻して固定の日本語の案内を出す。
- タイトル。完了したものは取り消し線と「済」（色だけに頼らない）。
- 期限と発生元の1行：
  - 期限：日付だけなら「10/9（金）まで」、日時なら「10/6（火）20:00 まで」、今日なら「今日まで」（強調）、過ぎていれば「期限を過ぎています」（強調）、なしなら出さない、不明なら「期限を確認できません」。
  - 発生元：持ち物からの自動は「持ち物から自動」。手動は出さない。
  - 持ち物からの自動のやることには、その予定の持ち物を添える（例「水筒、レジャーシート」）。
- 担当：担当がいれば、メンバー色の点と名前のチップ。いなければ、点線の「担当」ボタン。どちらも押すと、大人のメンバーと「担当なし」から選ぶ小さな一覧を、その行の中に開く（ダイアログを重ねない）。選ぶと、すぐに保存する。
- 手動のやることは、タイトルを押すと編集フォームを開く。自動のやることは、タイトルを押しても何も開かない（ボタンにしない）。

### 追加・編集フォーム（予定の作成ダイアログと同じ部品・同じ作り）

- 項目：タイトル（1〜200 文字）、期限（「なし」／「日付」／「日時」を選び、選んだものに応じて入力欄を出す。初期値は「なし」）、担当（大人のメンバー、または「担当なし」）。
- 「この予定にやることを追加」から開いたときは、フォームの上に予定のタイトルと日付を出す（変更はできない）。ヘッダーの「＋」から開いたときは、予定にひもづかないやることになる。
- 編集のときは、「削除」も出す（画面内で確認してから消す）。
- 保存中は操作を無効にし、失敗時は入力を残して固定の日本語の案内を出す。作成は `clientRequestId` を使い、連打や再送で二重に作られないようにする。未保存の入力があるときの PWA 更新の保留（`useReloadProtection`）は、予定の作成ダイアログと同じ扱いにする。

### 読み込み・取り直し・切り替え

- 初回は、カードの形の控えめなプレースホルダー。取得に失敗したら、案内と再試行。
- 操作（完了、担当、追加、編集、削除）のあとの取り直しは、裏で行う。取り直しの間、一覧を読み込み中の表示に差し替えない（「繰り返し」の画面と同じ扱い）。
- 別のタブから戻ったときは、前の一覧をすぐに出して、裏で取り直す。
- ログアウト・アカウント切替・家族の切替で、前の一覧を表示しない（query の鍵にユーザーと家族を入れ、既存の画面と同じ場所で消す）。
- 一覧が0件のときは、何をする画面かの短い説明と「やることを追加」ボタン。

## 計算（純粋関数にして `src/shared/domain` に置き、ユニットテストを付ける）

- 予定ごとのまとめ方と並び、「あと N日」、サマリーの数、期限の文、期限順の並び。日付と時刻は `src/shared/time` を通し、`Asia/Tokyo` で計算する。

## 変えないもの

- サーバー側の API、D1 のスキーマ、スコープ。
- 週ビュー、「週末の1日」、「繰り返し」、「家族」の画面。
- タブバーのほかの項目（「撮影」は「準備中」のまま）。

## テスト

- ユニット：まとめ方と並び、「あと N日」（今日・3日以内・過ぎた予定）、サマリーの数（今日まで・今週・担当未定、期限なし・不明の扱い、週の境目）、期限の文。
- Playwright（API をモック、合成データ）：
  - 3つの表示の切り替えと、それぞれの並び。サマリーの数。
  - 完了にする・戻す（すぐに切り替わること、失敗時に元に戻ること、取り直しの間に一覧が読み込み中にならないこと）。
  - 担当を決める・外す。
  - 手動のやることの追加（予定にひもづく・ひもづかない）、編集、削除。検証エラー、保存失敗で入力が残ること、連打で二重に作られないこと。
  - 自動のやることは、タイトルを押しても編集が開かないこと。持ち物が添えられること。
  - 予定が見つからない・取得できない場合のカード、0件のときの表示。
  - アカウントを切り替えたとき、前のアカウントのやることが表示されないこと。
  - 390px と 445px で横にはみ出さないこと。操作できるものが 44px 以上であること。
- 既存のテストがすべて通ること。

## 受け入れ基準

- 「やること」タブで、家族のやることを予定ごと・期限順・自分の担当で見られる。

- 持ち物からの自動のやることに、その予定の持ち物が添えられている。
- `src/worker` と `migrations` に変更がない。
- `pnpm typecheck` / `lint` / `test` / `e2e` が通る。`pnpm db:generate` で差分が出ない。
