## 指摘 1（修正が必要）：やることを裏で取り直している間、締切のチップと残りの数が消える

`src/client/features/week/WeekPage.tsx` の `taskDataIsCurrent` が、`!tasksQuery.isFetching` を条件にしている。そのため、次のときに、表示していたチップと「やること 残り N 件」がいったん消え、取り直しが終わるとまた出る。

- アプリに戻ってきたとき（画面のフォーカスで、やることを取り直す）。
- 別のタブ（「やること」など）から週ビューに戻ったとき（キャッシュがあっても、取り直しが終わるまで出ない）。
- 通信が復帰したとき。

チップが消えると行の高さが変わるので、戻るたびに画面が上下に動く。「繰り返し」の画面で直した「ちらつき」と同じ種類の問題になる。

### 直し方

- **同じユーザー・同じ家族のキャッシュがあれば、取り直しの間も、それを表示したままにする。** 取り直しが届いたら、差し替える（「やること」「繰り返し」の画面と同じ扱い）。
- 取り直しに失敗したときも、前に取得できていた内容を表示したままにする（エラーの案内は出さない）。初回の取得に失敗したときは、これまでどおり、チップと印を出さない。
- **別のアカウント・別の家族の内容を表示しない、という保証は、そのまま保つ。** 保証は、query の鍵（ユーザーと家族）と、切替時にキャッシュを消す既存の処理で行う。「取得中は出さない」という条件で代用しない。既存のテスト（`does not show the previous family task response after identity changes while it is pending` など）が、そのまま通ること。
- 初回（キャッシュがないとき）の扱いは変えない：やることを待たずに週ビューを表示し、届いたらチップを足す。

### テスト（Playwright、`e2e/week-tasks.spec.ts`）

- チップと残りの数が表示された状態で、やることの取り直しを遅らせて、画面のフォーカスを戻す。**取り直しの間も、チップと残りの数が表示されたまま**で、行とカードの高さが変わらないこと。取り直しが届いたら、新しい内容に差し替わること。
- 「やること」の画面へ移って週ビューに戻ったとき（取り直しを遅らせる）、前のチップがすぐに表示されること。
- 取り直しが失敗したとき、前のチップが表示されたままで、エラーの案内が出ないこと。
- 「やること」の画面で完了にしてから週ビューに戻ると、チップと残りの数が減っていること（既存のテストが、そのまま通ること）。
