## 目的

運動会のような単発の家族予定が、毎週の習い事の回と重なっているときに、それを知らせる。「繰り返し」の画面では、重なっている回から、そのまま「この回を休む」「振替を設定」に進めるようにする。

## 対象範囲

- 作るもの：重複を見つける純粋関数、「繰り返し」の画面での表示と解決への導線、週ビューでの印。
- 作らないもの：予定を作成・編集するときの警告（フォームの中での確認）、プリント取り込みとの連携（Phase 4）、個人予定との重なり（docs/03 の「公開まとめ」の分。Phase 6）、繰り返し予定どうしの重なり、自動での解決。
- **保存するものは増やさない。** D1 のスキーマは変えず、マイグレーションは追加しない。スコープも追加しない。

## 重複の決まり（`src/shared/domain/conflicts.ts` の純粋関数。Worker にも React にも依存させない）

「単発の家族予定」と「繰り返し予定の回」の組について、次をすべて満たすとき、重複とする。

1. **時間が重なる。**
   - 両方が時刻指定：区間が重なる（端点が接するだけなら、重ならない）。
   - 単発の予定が終日：その日（複数日なら、その期間の各日）にある繰り返し予定の回と重なる、とみなす。
   - 繰り返し予定の回が終日のものは、対象外（いまは作れない）。
2. **同じメンバーが関わる。** それぞれの予定の「関わるメンバー」を、対象メンバーと担当を合わせたものとする。対象メンバーが空の予定は、家族全員が関わるものとする。2つの予定の「関わるメンバー」に、共通の人が1人でもいること。
3. **どちらも確定。** 候補（`tentative`）の予定は、重複の対象にしない。
4. 繰り返し予定の回は、通常の回・振り替えた回・時刻を変えた回のどれでも対象にする（実際の日時で比べる）。休みにした回は対象にしない。

- 日付と時刻の計算は、`src/shared/time` のユーティリティを通し、`Asia/Tokyo` で行う。
- 返すもの：重なっている組の一覧（繰り返し予定の回、単発の予定、共通のメンバー）。

## API

- `GET /api/families/:id/routines` の `upcoming`（直近の回）の各回に、`conflicts`（重なっている単発の家族予定の一覧。なければ空）を足す。1件につき、予定の ID、タイトル、日時（終日かどうかを含む）。
  - そのために、家族カレンダーの予定を取得する。**取得は、一覧全体で1回だけ**（全シリーズの直近の回を覆う期間をまとめて `events.list` する。期間は、最も早い回の日の 0 時から、最も遅い回の翌日の 0 時まで。ページ数に上限を付ける）。シリーズごと・回ごとに取得しない。
  - 取得に失敗したとき、または上限に達したときは、一覧は返し、重複の情報だけを「確認できませんでした」の状態にする（重複がない、とは返さない）。
  - 家族カレンダーの予定なので、タイトルを返してよい。個人カレンダーは読まない。
- 週 API（`/week`）は変えない。週ビューの印は、週 API がすでに返している予定の一覧から、画面側で同じ純粋関数を使って求める。
- 認可・カレンダー ID の扱い・トークンは、既存の `GET /routines` のまま。

## 画面

### 「繰り返し」（`/routines`）

- 重なっている回のチップに、「重複」の印を足す（例「10/17（土）重複」）。色だけで区別しない。
- 重なっている回があるカードに、**解決パネル**を出す（重複があるときだけ）。
  - 文：「10/17（土）は『運動会』と重なっています」。重なっている予定が複数あれば、並べる。終日の予定は「（終日）」、時刻指定は時刻を添える。
  - ボタン：「この回を休む」「振替を設定」。押したときの挙動は、チップを押して出る操作（3-2）と同じものを使う（同じ API、同じフォーム）。新しい操作は作らない。
  - 重なっている回が複数あるときは、回ごとに1つずつ並べる。
- 回を休みにする・振り替えると、その回の重複が消え、パネルも消える（一覧を取り直す）。
- 重複を確認できなかったときは、カードに「重複を確認できませんでした」と控えめに出す。

### 週ビュー

- 重なっている2つの予定（単発の予定と、繰り返し予定の回）の両方に、「重複」の印を出す。通常の行のグレーのチップにも、「いつもと違う日」のカードにも、週末・祝日のカードにも出す。色だけで区別しない（アイコンと文字）。読み上げにも入れる。
- 印を押して何かを開く挙動は足さない（単発の予定は編集ダイアログ、繰り返し予定の回は「繰り返し」タブへの案内、のまま）。
- 平日に重複があっても、それだけでは日のレイアウトを変えない（単発の予定がある平日は、もともと「いつもと違う日」になる）。
- 「週末の1日」は、このタスクでは変えない。

## 変えないもの

- 繰り返し予定の作成・削除・休み・振替・祝日スキップの API と挙動。
- 単発の予定の作成・編集、週 API、空き状況、個人予定。
- D1 のスキーマ、マイグレーション、スコープ、デプロイ設定。

## テスト

- ユニット（`conflicts.spec.ts`）：
  - 時刻指定どうしの重なり、端点が接する場合（重複しない）、日をまたぐ予定。
  - 終日の単発の予定（1日・複数日）と、その日の回。
  - メンバーの決まり：共通のメンバーあり・なし、対象メンバーが空（全員）、担当だけが共通。
  - 候補の予定、休みの回が対象にならないこと。振り替えた回は実際の日時で判定されること。
  - 運動会（単発・土曜）とピアノ（毎週土）が重複として検出されること（docs/05 の受け入れ基準）。
- API：`upcoming` の各回の `conflicts`、家族カレンダーの予定の取得が一覧全体で1回であること（シリーズが複数あっても増えないこと）、取得の失敗・上限で「確認できませんでした」になり、一覧は返ること、ほかの家族の予定が混ざらないこと、認可。
- Playwright（API をモック）：
  - 「繰り返し」：重複のチップ、解決パネルの文、パネルから休む・振替を設定して、重複が消えること。重複を確認できなかったときの表示。390px と 445px。
  - 週ビュー：重なっている2つの予定の両方に印が出ること、重なっていない予定には出ないこと。
- 既存のテストがすべて通ること。

## 受け入れ基準

- 単発の家族予定と、同じメンバーの繰り返し予定の回が重なると、「繰り返し」の画面と週ビューで分かる。
- 「繰り返し」の画面の解決パネルから、その回を休みにする・振り替えることができ、重複が消える。
- 運動会（単発）とピアノ（毎週土）の重複が検出される。
