# タスク：「繰り返し」の回の操作を、押した瞬間に画面へ反映する

- ブランチ名: `perf/routines-instant-actions`（最新の main から分岐）
- 作業前に読むもの: [AGENTS.md](../../AGENTS.md)、[docs/20-routines.md](../20-routines.md)、`src/client/features/routines/RoutineInstances.tsx`、`src/client/features/routines/RoutinesPage.tsx`（`onChanged` で一覧のキャッシュを書き換えている箇所）、`src/worker/routes/routines.ts`（回の操作の共通処理。`events.get` を2回、`events.patch` を1回、順に呼んでいる）、`src/client/features/tasks/`（完了のチェックで、先に表示を切り替えて失敗時に戻している作りの参考）

## 背景

PR #35 のあとの実機確認で、「カクつきはなくなったが、ボタンを押してから表示が変わるまで3秒ほどかかる」という指摘があった。

原因：画面は、サーバーの応答を待ってから回の表示を変えている。サーバーは、1回の操作で Google を順に4回呼ぶ（トークンの取得、その回の取得、シリーズ本体の取得、変更）。

## 目的

「この回を休む」「休みを取り消す」「振替の保存」を押したら、すぐに表示が変わる。保存は裏で行い、失敗したら元に戻して知らせる。あわせて、サーバーの待ち時間も減らす。

## 対象範囲

### 画面（`src/client/features/routines/`）

- **押した時点で、その回の表示を先に切り替える。**
  - 「この回を休む」：その回を「お休み」にする。その回の重複の印と、解決パネルのその回の行も消す（休みの回は重複の対象にならないため）。
  - 「休みを取り消す」：その回を、元の日時の通常の回に戻す。自動のお休みの理由（祝日・年末年始）の表示は消す。
  - 「振替」の保存：入力した日時の回にする（元の日時と同じなら通常の回、違えば振替・時間変更。判定は、いまサーバーの応答に使っているのと同じ純粋関数 `getRoutineInstanceStatus` を使う）。フォームと、回の操作のメニューは、押した時点で閉じる。
  - 取り消し・振替で、重複があるかどうかは、画面では決めない（その回の重複の表示は、裏の取り直しが届くまで、前のまま）。
- 切り替える前に、一覧の取得中のリクエストを取り消し（`cancelQueries`）、切り替える前の内容を覚えておく。
- **保存中の扱い**：保存中の回のチップに、控えめな「保存中」の表示を出す（読み上げにも入れる。色だけに頼らない）。保存中は、同じ繰り返し予定のほかの操作（ほかの回、祝日の設定、削除）を、いまと同じく無効にする。ページ全体や、ほかの繰り返し予定のカードは無効にしない。
- **成功したら**：サーバーの応答の内容で、その回を確定する（いまの `onChanged` と同じ）。そのあと、一覧・週・空き状況を裏で取り直す（いまと同じ。取り直しの間、読み込み中の表示に差し替えない）。
- **失敗したら**：その回の表示を、切り替える前の内容に戻す。固定の日本語の案内を、その繰り返し予定のカードの中に出す（メニューは閉じているので、メニューの中ではなく、カードに出す）。振替の場合は、入力した日時を残してフォームを開き直す。401 のときの扱いは、いまと同じ。戻したあと、一覧を裏で取り直す（Google 側では変更が通っていた、という食い違いを直すため）。
- 保存中にアカウント・家族が切り替わったときは、結果を画面に反映しない（いまの `isIdentityCurrent` の扱いを保つ）。
- 未保存の入力があるときの PWA 更新の保留は、いまと同じ扱いにする（保存が終わるまで保留する）。

### サーバー（`src/worker/routes/routines.ts` の、回の操作の共通処理だけ）

- その回の取得（`events.get`）と、シリーズ本体の取得（`events.get`）を、**並べて同時に**呼ぶ（いまは順に呼んでいる）。取得後の確認（その回がそのシリーズのものか、本体が有効か）と、失敗時の応答（404、Google の失敗）は、いまと同じ結果になること。
- トークンの扱い（1つのリクエストの中だけ使い回す）は変えない。同時に呼んでも、トークンの取得は1回のままであること（PR #35 で、取得中の1回を共有する作りになっている）。
- ほかは変えない。

## 変えないもの

- API の入出力、検証、エラーコード。回の操作・祝日スキップ・重複の決まり。
- 祝日・年末年始の設定の切り替え（「適用中...」のまま。先に表示を切り替えない）。繰り返し予定の作成・削除。
- 「繰り返し」以外の画面、ほかのルート。
- D1 のスキーマ、マイグレーション、スコープ、デプロイ設定。トークンを保存しないこと。

## テスト

- API：
  - 回の操作で、その回と本体の取得が同時に始まること（片方の応答を待たずに、もう片方のリクエストが出ていること）。トークンの取得が1回であること。
  - 既存の回の操作のテスト（404、ほかのシリーズの回、本体が無効、Google の失敗、自動のお休みの上書きと巻き戻し）が、そのまま通ること。
- Playwright（API をモック。回の操作の応答を2秒遅らせる）：
  - 「この回を休む」を押した直後（応答の前）に、その回が「お休み」になり、「保存中」が出ること。重複のある回なら、解決パネルのその回の行が消えること。応答のあと、「保存中」が消えること。
  - 「休みを取り消す」「振替の保存」も、押した直後に表示が変わること。振替のフォームが、押した時点で閉じること。
  - 失敗したとき、表示が元に戻り、カードに案内が出ること。振替では、入力した日時を残してフォームが開き直ること。
  - 保存中に、同じ繰り返し予定のほかの操作ができず、ほかの繰り返し予定のカードは操作できること。
  - 連打しても、リクエストが1回であること。
  - 保存中にアカウントを切り替えたとき、前のアカウントの内容が表示されないこと。
  - 390px と 445px で、「保存中」の表示がはみ出さないこと。
- 既存のテストがすべて通ること。

## 受け入れ基準

- 回の操作のボタンを押すと、サーバーの応答を待たずに、その回の表示が変わる。
- 失敗したときは、表示が元に戻り、利用者に分かる。
- 回の操作の API の結果（成功・失敗の応答）が、これまでと変わらない。
- `migrations` に変更がない。`src/worker` の変更は `routines.ts` だけ。
- `pnpm typecheck` / `lint` / `test` / `e2e` が通る。`pnpm db:generate` で差分が出ない。
