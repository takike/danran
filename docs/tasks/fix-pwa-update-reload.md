# PWA の更新が反映されにくい問題の修正

- ブランチ名: `fix/pwa-update-reload`（最新の main から分岐）
- 作業前に読むもの: [AGENTS.md](../../AGENTS.md)、[docs/07-pwa-verification.md](../07-pwa-verification.md)、`vite.config.ts` の VitePWA 設定

## 背景

staging にデプロイしても、利用者の画面は2回再読み込みするまで前のバージョンのままになる。新しい Service Worker が有効になっても、開いているページは古いファイルで動き続けるため。人間による確認で、デプロイのたびに発生している。

## やること

1. 新しい Service Worker がページの制御を引き継いだとき（`controllerchange`）に、ページを1回だけ自動で再読み込みする。
   - 初回インストール時（それまで controller がなかった場合）は再読み込みしない。
   - 再読み込みが連続しないようにする（無限ループの防止）。
2. 入力中の内容が失われる状況では自動で再読み込みせず、「新しいバージョンがあります」というバナーと「更新」ボタンを出す。
   - 対象：オンボーディングの入力中、予定の作成・編集ダイアログを開いているとき（タスク 1-8 が未マージなら、後から対象を追加できる仕組みにしておく）。
3. アプリを開いたままでも更新に気づけるよう、画面が再び表示されたとき（`visibilitychange`）に Service Worker の更新確認を行う。頻度は抑える。
4. API をキャッシュしない、オフライン時のフォールバックなど、既存の挙動は変えない。

## テスト

- Playwright：古い Service Worker が制御している状態から新しいバージョンに切り替わると、再読み込み1回で新しい内容になること。初回インストールでは再読み込みしないこと。入力中はバナーが出て、自動では再読み込みされないこと。
- 既存の PWA・認証・オンボーディング・週ビューの E2E が通ること。

## 受け入れ基準

- デプロイ後、開いているページが再読み込み1回以内で新しいバージョンになる。
- 入力中の内容が勝手に消えない。
- `pnpm typecheck` / `lint` / `test` / `e2e` が通る。

PR を作成したらマージせずに止まること。
