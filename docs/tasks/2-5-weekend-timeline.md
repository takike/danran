# タスク 2-5：週末カードの空きタイムライン

- ブランチ名: `phase2/2-5-weekend-timeline`（最新の main から分岐）
- 作業前に読むもの: [AGENTS.md](../../AGENTS.md)（特に「絶対に守ること」1・2・5、UI の規約）、[docs/02-screens.md](../02-screens.md)（予定の見え方、S1 の「週末・祝日セクション」、モック `docs/mocks/01-week-view.png`）、[docs/03-architecture.md](../03-architecture.md)（「freeWindows：共通の空き」）、[docs/19-busy-sharing.md](../19-busy-sharing.md)（`/week/busy`）、`src/shared/domain/freeWindows.ts`、`src/client/features/week/WeekPage.tsx`
- **人間の確認が必要**（ほかのメンバーの空き状況を画面に出す）

## 目的

週ビューの週末・祝日カードに、家族それぞれの「埋まっている時間」と、全員が空いている時間帯（共通の空き）を表示する。週末の予定を立てるときに、いつ全員が空いているかが一目で分かるようにする。

## プライバシー（最優先）

- ほかのメンバーの個人の予定について画面に出すのは、**埋まっている時間帯だけ**。`/week/busy` が返す以上の情報を作らない・推測させない（どのカレンダー由来か、件数、などを出さない）。
- 取得した空き状況は、ブラウザの永続ストレージ（localStorage、IndexedDB、Service Worker のキャッシュ）に保存しない。メモリ上の query cache だけで扱い、ログアウト・アカウント切替・家族の切替で消す（`personal-week` と同じ扱い）。
- サーバー側の変更はしない（下の「変えないもの」）。

## 対象範囲

### データの取得（クライアント）

- `GET /api/families/:id/week/busy` を呼ぶ API 関数と query hook を足す。応答は共有の zod スキーマで検証する。
- 家族予定（`/week`）、自分の予定（`/week/personal`）、空き状況（`/week/busy`）は、互いに独立に取得する。**空き状況の取得に失敗・遅延しても、家族予定と自分の予定はこれまでどおり表示する。**
- 週を切り替えたとき、前の週の空き状況を新しい週のカードに出さない（応答の週と表示中の週が一致するときだけ使う）。

### 計算

- 1日ごとに、2-4 の `getFreeWindows` を使う。入力は、対象メンバー（active な大人と子ども全員）、`/week/busy` の区間（状態が `ready` の大人の分）、その日の家族予定。既定値（8〜20 時、30 分未満の空きは捨てる、担当の余裕 0 分）のまま使う。
- 「ルーティンを隠す」の切り替えは、計算に影響させない（隠していても、繰り返しの家族予定は埋まっている時間に数える）。
- 表示用の整形（バーの位置と幅の割合、合計時間の表記、読み上げ用の文）は `src/shared/domain` の純粋関数にして、ユニットテストを付ける。
- `getFreeWindows` は不正な入力で例外を投げる。例外が出ても週ビュー全体を壊さず、その日のタイムラインだけを「表示できません」にする。

### 画面（週末・祝日カードだけ。平日の行と「いつもと違う日」のカードは変えない）

- **空きタイムライン**：8〜20 時の横バーを、メンバーごとに1行ずつ並べる（順番は凡例と同じ）。行の左にメンバー色の点と名前。埋まっている時間帯を濃いグレーで塗る。時刻の目盛り（8・12・16・20）を付ける。
- **「共通」行**：最下段に置き、全員が空いている時間帯をアクセント色の帯で示す。色だけに頼らず、行のラベルと下の文で分かるようにする。
- **「みんな空き N時間」**：カードの日付の行の右側に出す。30 分単位で切り捨てる（例：3時間、3.5時間）。共通の空きが 0 のときは「みんな空きなし」。
- **読み上げ**：バーは装飾扱いにし、各行に同じ内容の文を付ける（例「（名前）：10:00–12:00、15:00–16:00 は予定あり」「共通の空き：12:00–15:00、16:00–20:00」）。
- **メンバーの状態による出し分け**

  | 状態 | その人の行 | 共通の空き・「みんな空き」 |
  |---|---|---|
  | 大人・`ready` | 個人の予定と家族予定の埋まっている時間 | 計算に含める |
  | 大人・`not_shared` | 家族予定の分だけを塗り、行に「個人の予定は未共有」と添える | 家族予定の分だけで計算し、カードに「個人の予定を共有していない人がいます」と添える |
  | 大人・`unavailable` | バーを出さず「取得できませんでした」 | **出さない**（空いていると誤解させないため）。「空き状況を取得できない人がいるため、共通の空きは表示していません」と出す |
  | 子ども | 家族予定の埋まっている時間 | 計算に含める |

- 空き状況の取得中は、タイムラインの場所に控えめな読み込み表示を出す。取得そのものに失敗したときは、タイムラインの場所にだけ「空き状況を読み込めませんでした」と出す（家族予定のリストはそのまま）。
- 本人が空き状況を共有していない（`not_shared`）ときは、自分の行の「未共有」の近くに「家族」タブへのリンクを1つ出す。
- 390px 幅で、名前が長くてもバーが極端に細くならないこと（名前は省略表示にし、バーの最小幅を確保する）。

## 対象範囲の外

- S2「週末の1日」への遷移、「予定を立てる」ボタン、空き帯をタップして予定を作ること（2-6）。カードのタップで何かを開く挙動は足さない。
- 平日の行への空き状況の表示。
- 自分の予定（「自分だけ」）の表示の変更。

## 変えないもの

- サーバー側の API（`/week`、`/week/personal`、`/week/busy`、設定）、D1 のスキーマ、認可。`src/worker` と `migrations` に変更を入れない。
- 家族予定のリスト、「自分だけ」の予定、予定の追加・編集、連休バッジ、「ルーティンを隠す」の既存の挙動。
- 平日セクションの見た目と高さ。
- 「家族」タブの画面。

## テスト

- ユニット（表示用の純粋関数）：バーの位置と幅、8 時より前・20 時より後にはみ出す区間、合計時間の表記（0、30 分、3.5 時間）、読み上げ用の文。
- Playwright（API をモック、合成データ）
  - 大人2人が `ready`：それぞれの行、共通の行、「みんな空き N時間」が、与えた区間どおりに出ること。
  - `not_shared` と `unavailable` の出し分け（`unavailable` のとき、共通の空きと「みんな空き」が出ないこと）。
  - `/week/busy` が 500 を返す・遅れるとき、家族予定と「自分だけ」の予定が表示され、予定の追加もできること。
  - 週を切り替えたとき、前の週の空き状況が残らないこと。ログアウト・アカウント切替で空き状況が残らないこと。
  - 平日の行と「いつもと違う日」のカードに、タイムラインが出ないこと。
  - 画面のどこにも、モックの応答に含めていない情報（カレンダー名など）が出ないこと。
  - 390px と 445px で横にはみ出さないこと。
- 既存のテストがすべて通ること。
