# タスク 3-5：振替した回を、週ビューで「いつもと違う日」として扱う

- ブランチ名: `phase3/3-5-routine-exceptions`（最新の main から分岐）
- 作業前に読むもの: [AGENTS.md](../../AGENTS.md)、[docs/01-concept.md](../01-concept.md)（「ルーティンは背景に、週末は前景に」）、[docs/02-screens.md](../02-screens.md)（S1）、[docs/03-architecture.md](../03-architecture.md)（「dayLayout：日ごとの表示サイズ」のルーティン判定）、[docs/15-week-api.md](../15-week-api.md)、[docs/20-routines.md](../20-routines.md)、`src/worker/routes/week.ts`、`src/shared/domain/dayLayout.ts`、`src/shared/domain/routineInstances.ts`

## 背景

docs/03 の決まりでは、「繰り返し予定の通常の回 ＝ ルーティン」「例外の回（振替・時間変更）と単発の予定 ＝ 非ルーティン」。いまの週 API は、繰り返し予定の回をすべてルーティンにしている。そのため、習い事を別の日に振り替えても、週ビューではグレーのチップのままで目立たず、「いつもと違う日」にならない。

## 目的

繰り返し予定のうち、日や時刻を変えた回を「いつもと違う予定」として扱い、週ビューで目立つようにする。振り替えた日は、平日なら「いつもと違う日」のカードに展開される。

## 対象範囲

### 週 API（`GET /api/families/:id/week`）

- いまの `isRoutine` は、「繰り返し予定の回かどうか」と「背景に回すかどうか」の2つの意味で使われている。これを分ける。
  - `isRecurring`（新規）：繰り返し予定の回なら true。**編集の可否と、繰り返しのアイコンは、これで決める。**
  - `isRoutine`：繰り返し予定の**通常の回**だけ true。日や時刻を変えた回は false。単発の予定は false（これまでどおり）。**レイアウト（compact / expanded）、グレーのチップ、「ルーティンを隠す」は、これで決める。**
- 通常の回かどうかの判定：その回の開始・終了が、元の予定日時（`originalStartTime`）と、シリーズの本来の長さから決まる時刻に一致すれば通常。1分でも違えば例外。判定は、3-2 で作った純粋関数（`getRoutineInstanceStatus`）を使うか、同じ決まりの純粋関数にまとめる。
  - シリーズの本来の長さを知るために、Google への呼び出しを増やさない。`events.list`（`singleEvents=true`）の応答だけでは本来の長さが分からない場合は、**開始時刻が元の予定日時と違うかどうか**だけで判定してよい（終了だけを変えた回は通常の回として扱う、という割り切り。docs に書く）。
- 例外の回には、`movedFrom`（元の予定日時。ISO 文字列）を足す。通常の回と単発の予定では `null`。
- `affectsAvailability` の決め方は変えない。

### 画面

- **週ビュー**：例外の回は、単発の家族予定と同じ見た目で出す（グレーのチップにしない。平日なら、その日が「いつもと違う日」のカードになる）。タイトルの近くに「振替」の印と、元の日付を出す（例「振替（10/20 から）」。同じ日の中で時刻だけ変えた場合は「時間変更」）。色だけで区別しない。
- 「ルーティンを隠す」は、例外の回を隠さない。
- **「週末の1日」**：例外の回にも、同じ「振替」「時間変更」の印を出す（幅に余裕があるブロックだけでよい。読み上げ用の一覧には必ず入れる）。
- **編集の扱いは変えない**：繰り返し予定の回（`isRecurring`）を選んだときは、通常の回でも例外の回でも、これまでどおり「休み・振替は『繰り返し』タブで設定できます」の案内を出し、単発の予定の編集ダイアログは開かない。いま `isRoutine` で分岐している編集の判定を、`isRecurring` に置き換える。
- 繰り返しのアイコン・「繰り返し」の文字も、`isRecurring` で出す（例外の回にも出る）。
- 「繰り返し」の画面は変えない。

### あわせて直すこと：週ビューのスクリーンショット

- `docs/screenshots/s1-week-view.png` を、いまは3つのテスト（`e2e/week-busy.spec.ts`、`e2e/weekend-day.spec.ts`、`e2e/personal.spec.ts`）が同じファイル名で書き出していて、実行順で内容が変わる。**1つのテストだけ**が書き出すようにする（週ビューの主な要素がそろうテストを1つ選ぶ。家族予定、ルーティン、例外の回、「自分だけ」、週末カードの空きタイムライン）。ほかの2つは、書き出しをやめる。

## 変えないもの

- 休みにした回の扱い（これまでどおり、週ビューに出ない）。
- 単発の予定の表示と編集、繰り返し予定の作成・休み・振替の API と画面。
- 空き状況の計算（例外の回も、これまでどおり、その時間が埋まっている扱い）。
- D1 のスキーマ、マイグレーション、スコープ。Google への呼び出しの数。

## テスト

- ユニット：通常の回・日を変えた回・時刻だけ変えた回・単発の予定の、`isRecurring` / `isRoutine` / `movedFrom` の判定。`dayLayout`：平日に例外の回だけがある日は `expanded`、通常の回だけの日は `compact`（既存のテストの期待値は、意味が変わらないことを確かめたうえで直す）。
- API：週 API の応答で、通常の回・例外の回・単発の予定の3つの項目が正しいこと。Google への呼び出しの数が増えていないこと。
- Playwright（API をモック）：
  - 平日に振り替えた回がある日が「いつもと違う日」のカードになり、「振替（10/20 から）」が出ること。
  - 「ルーティンを隠す」で、通常の回は消え、例外の回は残ること。
  - 例外の回を選んでも、単発の予定の編集ダイアログが開かず、「繰り返し」タブへの案内が出ること（通常の回も同じ）。
  - 「週末の1日」で、例外の回に印が出ること。
  - 390px と 445px。
- 既存のテストがすべて通ること。

## 受け入れ基準

- 振り替えた回・時刻を変えた回が、週ビューで単発の予定と同じように目立ち、平日なら「いつもと違う日」になる。
- 通常の回は、これまでどおりグレーのチップで、「ルーティンを隠す」で消える。
- 繰り返し予定の回を選んだときの案内は、例外の回でも変わらない（単発の編集ダイアログが開かない）。
- 週ビューのスクリーンショットを書き出すテストが1つだけになっている。
- `src/worker` の変更は週 API だけで、`migrations` に変更がない。
- `pnpm typecheck` / `lint` / `test` / `e2e` が通る。`pnpm db:generate` で差分が出ない。
