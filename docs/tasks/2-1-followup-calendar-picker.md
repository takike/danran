# タスク 2-1 フォローアップ：カレンダー選択の初期状態を「すべて未選択」にする

- ブランチ名: `phase2/2-1-followup-calendar-picker`（最新の main から分岐）
- 作業前に読むもの: [AGENTS.md](../../AGENTS.md)、[docs/18-personal-events.md](../18-personal-events.md)、[docs/tasks/2-1-review-fixes.md](2-1-review-fixes.md)
- **人間の確認が必要**（個人カレンダーの設定に触るため、マージは人間が行う）

## 背景

実機確認で、「家族」タブの「自分の予定の表示」が分かりづらいという指摘があった。保存した選択がないとき、主カレンダーにチェックが付いた状態で「現在、自分の予定は表示していません」と出るため、表示しているのかいないのかが読み取れない。

## 目的

保存した選択がないときは、チェックをすべて外した状態で見せる。画面のチェックが、いつも「いま実際に表示しているカレンダー」と一致するようにする。

## 対象範囲

### API（`GET` / `PUT /api/families/:id/personal-calendars`）

- 一覧の `selected` は、**保存されている行だけ**から決める。保存した選択がないときは、主カレンダーを含めてすべて `false` にする（主カレンダーを選択済みの下書きとして返すのをやめる）。
- `hasSavedSelection`、`isPrimary`、そのほかの項目と応答の形は変えない。

### 画面（`/family` の「自分の予定の表示」）

- 保存した選択がないとき：チェックはすべて外れた状態。案内文は「現在、自分の予定は表示していません。表示するカレンダーを選んで保存してください。」にする。
- 主カレンダーの「主」の表示は残す（選びやすくするため）。
- 何も選ばず、保存済みの選択もないときは、保存ボタンを押せないようにする（変更がないため）。保存済みの選択をすべて外して保存する操作は、従来どおりできる。

## 変えないもの

- 保存の仕組み（選んだカレンダーの行だけを保存、すべて外すと0行）、上限10件、`calendarList` にない ID の拒否。
- 段階的認可の流れ、`login_hint`、戻り先、エラーコード。
- `/week/personal` と週ビューの見た目・挙動。
- D1 のスキーマとマイグレーション。

## テスト

- Vitest：保存した選択がないとき、一覧のすべての `selected` が `false` であること（主カレンダーを含む）。保存後は、選んだものだけが `true` であること。
- Playwright：同意直後の画面でチェックがすべて外れていること、案内文が出ていること、1つ選んで保存すると案内が消えること、すべて外して保存すると再びチェックなし＋案内の状態に戻ること。
- 既存の「主カレンダーが選択済みの下書き」を前提にしたテストは、新しい仕様に合わせて直す。
- 既存のテストがすべて通ること。

## 受け入れ基準

- 保存した選択がないとき、カレンダーのチェックがすべて外れ、表示していない旨と次の操作が案内される。
- 画面のチェックと、週ビューに実際に表示されるカレンダーが一致する。
- `pnpm typecheck` / `lint` / `test` / `e2e` が通る。`pnpm db:generate` で差分が出ない。
