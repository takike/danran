- 作業前に読むもの: [AGENTS.md](../../AGENTS.md)、[docs/02-screens.md](../02-screens.md)（S4、モック `docs/mocks/04-routines.png`）、[docs/03-architecture.md](../03-architecture.md)（「繰り返し予定」）、[docs/20-routines.md](../20-routines.md)、[docs/16-event-editing.md](../16-event-editing.md)（`events.patch` の注意点）、`src/worker/routes/routines.ts`、`src/client/features/routines/RoutinesPage.tsx`

## 目的

「繰り返し」の画面で、それぞれの繰り返し予定の直近の回を見て、1回だけ休みにする・別の日時に振り替える、をできるようにする。習い事が1回休みになった、別の日に振り替えた、という日常の変更を、シリーズ全体を作り直さずに反映できるようにする。

## 対象範囲

- 作るもの：直近4回の表示、「この回を休む」と取り消し、「振替」と取り消し、例外（休み・振替）の表示。
- 作らないもの：シリーズ全体の内容の編集（曜日や時刻の変更）、祝日・年末年始・休園日のスキップ（3-3）、重複の検出と解決パネル（3-4）、振替した回を週ビューで「いつもと違う日」として扱うこと（3-5）、フィルタ。
- 変更は、Google の繰り返し予定の「個別の回」（instance）に対して行う。D1 には、回ごとの情報を保存しない（Google を正とする）。D1 のスキーマは変えず、マイグレーションは追加しない。

## API（`familySecurityMiddleware` を通す。入出力は共有の zod スキーマ）

共通：未ログインは 401、その家族の active な大人のメンバーでなければ 404。カレンダー ID は必ず DB の `families.family_calendar_id` を使う。Google への呼び出しはリクエストした本人のトークンで行い、`sendUpdates` は `none`。変更系の検査（`X-Requested-With`、`Origin`、ボディサイズ上限）は既存の変更系 API と同じ。

### 直近の回

- `GET /api/families/:id/routines` の各項目（状態が `ready` のもの）に、`upcoming`（直近の回の一覧。最大4件）を足す。
  - Google の `events.instances` を、いま（`Asia/Tokyo`）以降・`showDeleted=true` で呼び、**元の予定日時（`originalStartTime`）の順で、今日以降の4回**を返す。振り替えで別の日に動いた回も、元の予定日の位置に並べる。
  - 各回に返すもの：回の ID、元の日付と時刻、実際の日付と時刻、状態（`normal` 通常／`skipped` 休み／`moved` 振替）。
  - 状態の決め方：Google の `status` が `cancelled` なら `skipped`。実際の開始・終了が、元の日時（と、シリーズの長さ）と違えば `moved`。それ以外は `normal`。
  - 回の取得に失敗したシリーズは、一覧全体を失敗にせず、その項目の `upcoming` を「取得できませんでした」の状態にする。
- Google への呼び出しが増える（シリーズ1件につき2回）。シリーズは少数の前提でよいが、並列数に上限（例：4）を付ける。

### 回の変更（すべて `routineId` と回の ID を受け取る）

- `POST /api/families/:id/routines/:routineId/instances/:instanceId/skip` … その回を休みにする（`events.patch` で `status: "cancelled"`）。
- `POST …/instances/:instanceId/restore` … 休み・振替を取り消して、元の日時の通常の回に戻す（`status: "confirmed"`、開始・終了を元の日時に戻す）。
- `POST …/instances/:instanceId/move` … 別の日時に振り替える。入力は、新しい日付、開始・終了の時刻（同じ日の中）。`status` は `confirmed` にする（休みにしていた回を振り替えることもできる）。
- 共通の決まり：
  - **回の ID を信用しない。** `routineId` から D1 の行を引き、Google から回を取得して、その回の `recurringEventId` が行の `recurring_event_id` と一致し、家族カレンダー上にあることを確かめてから変更する。一致しなければ 404。ほかの家族・ほかのシリーズ・単発の予定の ID では変更できないこと。
  - 開始・終了を送るときは、`dateTime` と `timeZone: "Asia/Tokyo"` を送り、使わない `date` は `null` で送る（`events.patch` は入れ子のオブジェクトをマージするため。docs/16 の決まり）。
  - 対象メンバー・担当などの `extendedProperties.private` は変えない。
  - 同じ操作を2回送っても、同じ結果になること（すでに休みの回を休みにする、など）。
  - 振替先が過去の日付でも受け付ける（記録のため）。振替先の日付は、対応年の範囲（1970〜2050）に限る。
- 応答は、変更後のその回（一覧の `upcoming` と同じ形）。

## 画面（`/routines`）

- 繰り返し予定のカードに、**直近4回の日付チップ**を足す（例「10/20（火）」）。
  - 休みの回：取り消し線と「お休み」。色だけで区別しない。
  - 振替の回：「10/20 → 10/22（木）振替」。時刻も変わっていれば、時刻も出す。
  - 取得できなかったとき：チップの場所に「直近の回を取得できませんでした」と再試行。
- チップは本物の `<button>` にし、押すとその回の操作を出す（カードの中に展開する。ダイアログを重ねない）。
  - 通常の回：「この回を休む」「振替を設定」。
  - 休みの回：「休みを取り消す」「振替を設定」。
  - 振替の回：「振替を取り消す（元の日時に戻す）」「振替先を変える」。
  - 「振替を設定」は、日付・開始時刻・終了時刻の入力（初期値は、その回の元の日付と時刻）と「保存」「やめる」。
- 操作中は、そのカードの操作を無効にする（連打防止）。失敗時は、固定の日本語の案内を出し、表示は変更前のままにする。成功したら、その回のチップを更新する。
- 操作のあと、週ビューと「週末の1日」にも反映される（週の query を無効化する）。
- 未保存の振替の入力があるときの PWA 更新の保留（`useReloadProtection`）は、作成フォームと同じ扱いにする。
- 週ビューと「週末の1日」で繰り返し予定を選んだときの案内を、「繰り返し予定の変更は準備中です。」から、「この予定は繰り返し予定です。休み・振替は『繰り返し』タブで設定できます。」に変え、「繰り返し」タブへのリンクを添える。それ以外の挙動は変えない。

## 変えないもの

- 繰り返し予定の作成・一覧の既存の項目・シリーズ全体の削除（3-1）。
- 単発の予定の API と画面。繰り返し予定の回を、単発の予定の PATCH / DELETE で変更できないこと（これまでどおり固定コードで拒否）。
- 週 API の `isRoutine` の決め方（振替した回の扱いは 3-5）。
- D1 のスキーマ、既存のマイグレーション、スコープ。

## テスト

- API：
  - 直近の回：通常・休み・振替が混ざったときの並びと状態、4件に切ること、今日より前の回が出ないこと、回の取得に失敗したシリーズだけが「取得できませんでした」になること。
  - 休む／取り消す／振替：Google に送る本文（`status`、`dateTime`、`timeZone`、`date: null`）、同じ操作の再送、休みの回の振替、振替の取り消しで元の日時に戻ること。
  - **回の ID の検証**：ほかのシリーズの回、ほかの家族の回、単発の予定の ID、存在しない ID で 404 になり、Google の変更が呼ばれないこと。
  - 入力の検証：終了が開始より前、不正な日付、対応年の範囲外。
  - 認可：未ログイン 401、非メンバー 404、変更系の検査。
  - `extendedProperties.private` を変えないこと。
- ユニット（純粋関数）：回の状態の判定（通常・休み・振替、時刻だけの変更）、チップの表示文。
- Playwright（API をモック）：チップの表示（3種類）、休む・取り消す、振替の設定・変更・取り消し、失敗時に表示が変わらないこと、連打、週ビューの案内文とリンク、390px と 445px。
- 既存のテストがすべて通ること。

## 受け入れ基準

- 「繰り返し」の画面で、各予定の直近4回が見える。
- 1回だけ休みにでき、取り消せる。Google カレンダーでも、その回だけが消える・戻る。
- 1回だけ別の日時に振り替えられ、取り消せる。Google カレンダーでも、その回だけが動く。
- ほかのシリーズやほかの家族の回を変更できないことが、テストで保証されている。
- D1 のスキーマに変更がない。
- `pnpm typecheck` / `lint` / `test` / `e2e` が通る。`pnpm db:generate` で差分が出ない。
