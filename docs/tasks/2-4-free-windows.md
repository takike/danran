# タスク 2-4：共通の空きを計算するドメインロジック（`freeWindows`）

- ブランチ名: `phase2/2-4-free-windows`（最新の main から分岐）

## 目的

1日について、メンバーごとの「予定あり」の区間と、家族全員が空いている時間帯（共通の空き）、その合計時間を計算する純粋関数を作る。**このタスクでは計算だけを作る。API・画面・Google の呼び出し・D1 は触らない。**

## 対象範囲

`src/shared/domain/freeWindows.ts` と `freeWindows.spec.ts` を新規に作る。Worker にも React にも依存させない。

### 入力

- 対象の日（`DateKey`）。
- 対象時間帯：開始時・終了時（既定 8 時〜20 時、`Asia/Tokyo`）。引数で変えられるようにする。
- 対象メンバー：ID の一覧（大人・子どもの両方）。
- 個人の busy 区間：メンバー ID ごとの `{ start, end }` の一覧（ISO 文字列）。2-3 で `freeBusy.query` の結果を渡す想定。このタスクでは入力として受け取るだけ。
- 家族予定の一覧：既存の `WeekEvent`（`src/shared/schemas/week.ts`）のうち、計算に必要な項目（時刻、対象メンバー、担当、候補／確定）。空き計算に含めるかどうかのフラグ（`affectsAvailability`、省略時 true）を受け取れるようにする。
- 切り捨てる最小の空き時間（既定 30 分）。
- 担当の前後に足す余裕（分。既定 0）。

### 計算の決まり

1. メンバーの busy ＝ 個人の busy 区間 ＋ そのメンバーが対象の家族予定 ＋ そのメンバーが担当の家族予定（前後に余裕を足す）。
2. 家族予定の対象メンバーが空のときは、家族全員が対象とみなす。
3. **候補（`tentative`）の家族予定は busy に含めない。**（候補は共通の空きの上に重ねて見せる設計のため。）
4. **終日の家族予定は busy に含めない。**（Google の既定と同じ扱い。記念日やゴミの日のような終日予定で、空きが消えないようにする。）
5. `affectsAvailability` が false の家族予定は busy に含めない。
6. busy 区間は対象時間帯で切り取り、重なる区間・端点が接する区間は1つにまとめる。
7. 共通の空き ＝ 対象時間帯から、全対象メンバーの busy の和集合を除いた残り。最小の空き時間に満たない区間は捨てる。
8. 対象メンバーが0人のときは、共通の空きを空にする。
9. 日付と時刻の計算は、すべて `src/shared/time` のユーティリティを通し、`Asia/Tokyo` で行う。足りないユーティリティは `src/shared/time` に足す。

### 出力

- メンバーごとの、まとめた後の busy 区間（対象時間帯の中だけ）。
- 共通の空きの区間の一覧。
- 共通の空きの合計（分）。

出力には、区間の開始・終了とメンバー ID だけを含める。予定のタイトルなどは含めない。

## 変えないもの

## テスト（`freeWindows.spec.ts`）

- 予定がない日は、対象時間帯の全体が共通の空きになる。
- 端点が接する busy、重なる busy がまとめられる。
- 対象時間帯の外にはみ出す busy、日をまたぐ busy（前日夜〜当日朝、当日夜〜翌日）が正しく切り取られる。
- 30 分未満の空きが捨てられ、ちょうど 30 分の空きは残る。
- 対象メンバーが空の家族予定は、全員の busy になる。
- 候補の予定、終日の予定、`affectsAvailability` が false の予定は busy にならない。
- 担当の予定は、担当者の busy になる（余裕を足した場合の前後も含む）。
- 子どもは家族予定だけで busy が決まる（個人の busy がなくても計算できる）。
- 対象メンバーが0人のとき。
- 合計時間の計算。
