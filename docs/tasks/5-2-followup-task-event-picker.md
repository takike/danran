# タスク 5-2 フォローアップ：「やること」の画面から、予定を選んでやることを足す

- ブランチ名: `phase5/5-2-task-event-picker`（最新の main から分岐）
- 作業前に読むもの: [AGENTS.md](../../AGENTS.md)（特に「絶対に守ること」のプライバシーの項、UI の規約）、[docs/21-tasks.md](../21-tasks.md)、`src/shared/schemas/tasks.ts`、`src/worker/routes/tasks.ts`（`verifyEventLink`、一覧での予定の取得）、`src/client/features/tasks/TaskDialog.tsx`、`e2e/tasks.spec.ts`

## 背景

実機確認での要望：「予定にひもづけたやることを、『やること』の画面からも作れるとよい」。

いまは、予定のカードの「＋ この予定にやることを追加」からしか、予定にひもづくやることを作れない。カードは、すでにやることがある予定にしか出ないので、**やることがまだ1つもない予定には、ひもづけられない**。

## 目的

「やること」の画面のフォームで、家族カレンダーのこれからの予定を選んで、やることをひもづけられるようにする。

## 対象範囲

- 作るもの：ひもづける予定の候補を返す API、フォームの「予定」の欄。
- 作らないもの：週ビューや予定のダイアログからやることを足す導線（5-3）、繰り返し予定の回へのひもづけ、過去の予定へのひもづけ。
- **保存するものは増やさない。** D1 のスキーマは変えず、マイグレーションは追加しない。スコープも追加しない。

## API（`familySecurityMiddleware` を通す。入出力は共有の zod スキーマ）

- `GET /api/families/:id/tasks/event-candidates`
  - 家族カレンダーの、**今日の 0 時（`Asia/Tokyo`）から 60 日後まで**の予定を返す。開始の早い順。
  - 各項目：予定の ID、タイトル、日時（終日かどうかを含む。一覧の `linkedEvent` の `time` と同じ形）、対象メンバー。
  - 含めないもの：繰り返し予定の回（通常の回も、振り替えた回も）、キャンセルされた予定。候補（`tentative`）の予定は含める。
  - Google の取得は `events.list`（`singleEvents=true`）を使い、ページ数に上限を付ける（2 ページ）。上限に達したときは、取れた分を返し、「続きがある」ことを応答に入れる。
  - **読むのは家族カレンダーだけ。** 個人カレンダーは読まない。カレンダー ID は DB の値だけを使う。Google への呼び出しは、リクエストした本人のトークンで行う。
  - 認可は、既存のやることの API と同じ：未ログインは 401、その家族の active な大人のメンバーでなければ 404。
  - D1 も Google も変更しない（共通の認証の処理は、これまでどおり）。
- 既存の `POST /tasks`・`PATCH /tasks/:taskId` は変えない（`eventId` の検証は、いまのまま。候補にない ID を送られても、いまの検証で判定する）。

## 画面（`src/client/features/tasks/`）

- 追加・編集フォームに、「予定」の欄を足す。本物の `<select>` と `<label>` を使う（タップ領域は 44px 以上）。
  - 選択肢：先頭に「ひもづけない」。続けて、候補の予定を「10/17（土）運動会」の形で（終日でなければ時刻も添える）。
  - **ヘッダーの「＋」から開いたとき**：初期値は「ひもづけない」。
  - **手動のやることの編集**：初期値は、いまひもづいている予定。その予定が候補にない場合（過去の予定など）は、その予定を選択肢に足して選んだ状態にする。「ひもづけない」に変えると、ひもづけを外す。
  - **予定のカードの「＋ この予定にやることを追加」から開いたとき**：いまのまま（予定のタイトルと日付を表示するだけで、変更できない。「予定」の欄は出さない）。
- 候補は、フォームを開いたときに取得する。取得中は、欄を「読み込み中...」にして、ほかの項目は入力できる。取得に失敗したときは、欄の下に案内と「再試行」を出し、**予定にひもづけないやることは、そのまま保存できる**（編集のときは、いまのひもづけを変えない）。
- 「続きがある」ときは、欄の下に「60 日以内の予定の一部を表示しています」と出す。
- 候補が0件のときは、「ひもづけない」だけの欄にし、「これからの予定がありません」と添える。
- 保存の送り方：作成は `eventId`（選んだ予定の ID、または `null`）。編集は、ひもづけを変えたときだけ `eventId` を送る。
- 保存のときに、選んだ予定がもうなかった（`INVALID_INPUT`）・繰り返し予定だった（`RECURRING_EVENT_UNSUPPORTED`）場合は、入力を残して、固定の日本語の案内を出す。
- 候補の query の鍵に、ユーザーと家族を入れる。ログアウト・アカウント切替・家族の切替で、前の候補を表示しない。

## 変えないもの

- やることの一覧・作成・更新・削除の API の入出力と検証。持ち物からの自動生成、予定への追従。
- 「予定ごと」「期限順」「自分の担当」の表示、行、サマリー。自動のやることは、編集できないまま。
- 週ビュー、予定のダイアログ、ほかの画面。
- D1 のスキーマ、マイグレーション、スコープ、デプロイ設定。

## テスト

- API：
  - 期間（今日の 0 時から 60 日後。日付の境目）、並び、繰り返し予定の回・キャンセルされた予定が含まれないこと、候補の予定が含まれること。
  - Google の呼び出しが、家族カレンダーへの `events.list` だけであること（**個人カレンダーを読んでいないこと**）。カレンダー ID が DB の値であること。
  - ページの上限と「続きがある」の応答。Google の失敗時の応答。
  - 認可：未ログイン 401、非メンバー 404、**ほかの家族の予定が返らないこと**。
  - D1 と Google を変更しないこと。
- Playwright（API をモック、合成データ）：
  - 「＋」から開いて予定を選び、その予定にひもづくやることができること（送る本文の `eventId`）。「ひもづけない」のままなら、`eventId` が `null` であること。
  - 編集で、ひもづけを変える・外す。ひもづけを変えないときは、`eventId` を送らないこと。いまの予定が候補にない場合の表示。
  - 予定のカードから開いたときは、欄が出ず、いまのままであること。
  - 候補の取得中・失敗（再試行、ひもづけないやることは保存できること）・0件・「続きがある」の表示。
  - 保存時のエラーで、入力が残ること。
  - アカウントを切り替えたとき、前のアカウントの候補が表示されないこと。
  - 390px と 445px で、欄と長いタイトルの選択肢が横にはみ出さないこと。
  - `DANRAN_SCREENSHOTS=1` を付けない `pnpm e2e` のあと、`git status` に変更が出ないこと。
- 既存のテストがすべて通ること。

## 受け入れ基準

- 「やること」の画面の「＋」から、これからの家族予定を選んで、やることをひもづけられる。やることがまだない予定にも、ひもづけられる。

- `migrations` に変更がない。
- `DANRAN_SCREENSHOTS=1` を付けない `pnpm e2e` で、作業ツリーが変わらない。
- `pnpm typecheck` / `lint` / `test` / `e2e` が通る。`pnpm db:generate` で差分が出ない。
