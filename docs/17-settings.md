# 17. 家族設定 API と画面（Task 1-9）

`/family` で active メンバーの表示名・色と、家族の休園日を管理します。Google Calendar への書き込みや追加の OAuth scope は行いません。既存の `members` と `closure_days` を使い、D1 スキーマ変更はありません。

## 権限とエラー

すべての家族 API はセッションと家族所属を検証します。メンバー設定・休園日変更を行えるのは、対象家族の active な大人メンバーです。家族オーナーである必要はありません。未ログインは `401 UNAUTHORIZED`、active な大人でない呼び出し元や対象家族・メンバーが見つからない場合は `404 NOT_FOUND`、不正な入力は `400 INVALID_INPUT`、Origin 等の CSRF 検証失敗は `403 FORBIDDEN` です。クライアントは固定の日本語案内だけを表示し、API や内部の生エラーを表示しません。

この権限変更はメンバーの追加・削除や招待発行には及びません。子どもの追加・削除と招待発行は従来どおりオーナー限定で、`/onboarding` に残ります。

## API

入出力は `src/shared/schemas/settings.ts` および `src/shared/schemas/family.ts` の共有 Zod スキーマを正本とします。変更系 API の本文上限は16 KiBです。

| メソッド | パス | 入力 | 成功レスポンス |
|---|---|---|---|
| `PATCH` | `/api/families/:familyId/members/:memberId` | `{ "name": "表示名", "color": "coral" }` | `200 { "family": FamilyPublic }` |
| `GET` | `/api/families/:familyId/closures` | なし | `200 { "closures": ClosureDay[], "hasMore": boolean }` |
| `POST` | `/api/families/:familyId/closures` | `{ "startDate": "2026-10-08", "endDate": "2026-10-09", "label": "行事準備", "memberIds": ["mem_child"] }` | `201 { "closures": ClosureDay[] }` |
| `DELETE` | `/api/families/:familyId/closures/:closureId` | なし | `200 { "ok": true }` |

### メンバーの変更

PATCH は指定家族の active メンバー（大人・子ども）の `name` と `color` だけを更新します。名前は既存の `memberNameSchema`（前後の空白を含めず1〜80文字）、色は `indigo`, `green`, `ochre`, `purple`, `coral`, `teal`, `rose`, `slate` の8色です。色の重複は許可します。`kind`, `userId`, `sortOrder`, `status` は変更しません。レスポンスは更新後の家族全体で、メンバー順は大人→子ども、`sortOrder`、ID の順です。

### 休園日の一覧・登録・削除

- GET は Asia/Tokyo の今日以降を日付・ID 順で最大200件返します。`hasMore` はこの上限を超える残りがある場合に `true` です。
- POST の `startDate` は必須、`endDate` は省略可能で、省略時は開始日と同じ日です。開始日・終了日の両端を含み、期間は最大31日です。`label` は前後の空白を除いて1〜40文字。祝日データの対象範囲は1970〜2050年です。
- `memberIds` は最大100件の active な同一家族メンバー ID です。重複 ID は一度にまとめ、ID の順序にかかわらず同じ対象集合として扱います。空配列は家族全員を対象にします。
- POST は日付ごとに1行を作ります。同じ家族・日付・trim 後のラベル・対象メンバー集合が既にあれば重複行を作らず、その既存行も含めた正規化後の行を日付順に返します。
- DELETE は同一家族の行だけを削除します。既に存在しない行や他家族の ID でも `{ "ok": true }` を返し、他家族のデータは削除しません。

休園日を登録すると、週 API が返す `closures` にラベルと有効な対象メンバーを含め、`dayLayout` が該当日を `weekend-card` として返します。週 API の契約や `dayLayout` の仕様は変更しません。設定の保存・削除が成功すると、家族と週のクエリを再取得し、凡例・予定の色ドット・休園日カードに反映します。

## 画面と入力保護

「家族」タブに「メンバー」と「休園日」のセクションを表示します。各 active メンバーの表示名・色を編集し、色は色名付きで選択します。`slate` の UI 表示名は「グレー」です（共有識別子は `slate` のままです）。休園日は今日以降の一覧、開始・終了日、ラベル、対象メンバーの追加フォームを持ち、削除前に画面内で確認します。色だけに頼らず色名も表示し、すべての操作部品は44px以上のタップ領域にします。

保存中・削除中の多重送信は同期 ref で防ぎ、処理中は該当操作を無効にします。通信・入力エラーではフォームの値を保持し、固定メッセージを表示します。ユーザーが編集した未保存値または保存処理中は PWA 自動更新を保留し、更新バナーからの手動適用も保存中は無効にします。

## Staging での手動確認

このタスクでは実 Google Calendar / staging の確認は行っていません。コードが staging に自動デプロイされた後、人間が既存の staging アカウントで次を確認してください。追加 scope、Google Calendar の変更、新しいアカウント設定は不要です。

1. オーナー以外の active な大人でログインし、「家族」を開く。自分以外を含む active メンバーの表示名と色を変更して保存できることを確認する。
2. 週ビューの凡例で新しい名前と色が反映され、対象メンバーの予定の色ドットにも同じ色が反映されることを確認する。
3. 「休園日」で1日の休園日を登録し、週ビューの該当日にラベル付きカードが出ることを確認する。期間指定では開始・終了日を含む各日が対象になることも確認する。
4. 休園日の削除を開始し、確認をキャンセルすると一覧に残ること、確認後に削除すると週ビューと一覧から消えることを確認する。
5. 31日を超える期間と空白だけのラベルは保存されず、入力が保持されることを確認する。

既存の「家族の設定」（`/onboarding`）にある子どもメンバーの追加・削除、招待発行はオーナー限定のままです。staging アカウントを用いた上記の人間による確認は未実施です。
